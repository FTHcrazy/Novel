## 一、背景与目标

### 背景

行囊当前是「跑团式 CRPG 角色面板」：10 个模块（总属性汇总 / 人物属性 / 属性映射 / 装备栏 / 物品栏 / 技能栏 / 境界 / 货币 / 状态效果 / 备注速记），外加模块管理、单位系统、槽位管理、分类管理、来源抽屉、记录抽屉等 7 个以上管理器与浮层。作者的真实核心用途（v1.2 评审确认）是**数值统计与盘点**——系统流点数、灵石、物品数量这类「随剧情增减的资源」，作者需要随时加减、随时核对账实，防止写到后面与前文数目冲突（吃书）。两者错配：

- 「物品栏 / 货币 / 属性」各自独立成模块，一笔「花了 500 灵石买丹药」要跨三个模块手工同步，没有统一的流水与余额概念；
- 「总属性汇总」依赖 属性定义→基础值→映射→装备加成 整条链路，孤立使用语义不成立；
- 概念密度高（分区仪表盘、三档断点折叠、钉选、多管理器），没有分级引导；
- 结果是「明明有该功能，却因花费心智太多而废弃，宁愿手动文本记录」。

### 目标与成功指标

| 目标 | 衡量口径 | 备注 |
|---|---|---|
| 打开即记账：新书首次打开行囊 30 秒内完成一次加减（记一笔） | 可用性自测观察（估算值，无埋点基础） | 估算，待数据验证 |
| 账实一致：任何资源当前余额可追溯（流水可查、盘点可对） | 静态验收：余额 = 流水累计；盘点修正留痕 | 可测试验收 |
| 零配置：默认形态不出现 CRPG 概念（属性映射 / 槽位 / 进制 / 熟练度阈值） | 默认态界面审查：CRPG 词汇出现数＝0 | 可静态验收 |
| 不伤害进阶用户：数值模块功能与数据不删不改，仅收纳 | 现有 CharacterPack 全量测试通过 | 硬性验收 |

### 名词与术语

| 术语 | 定义 |
|---|---|
| 盘点台账 | 行囊的默认形态：一张资源表，每行「资源名 + 当前数量」，快捷加减即记账 |
| 资源条目 | 台账上的一条可计数资源，分两型：**余额型**（纯数量：灵石 / 积分 / 抽奖券）与**进度型**（当前值 / 可选上限：经验 500/6000、好感度 65/100、熟练度） |
| 记账流水 | 每次增减产生的一条记录：时间 / 章节 / 增减量 / 变动后余额 / 备注 |
| 盘点核对 | 作者按剧情手动输入某资源的「实际应有数」，差值自动生成修正流水，账实归一 |
| 进阶面板 | 收纳现有 10 个数值模块的区域，从台账主动进入才可见 |
| 资源模板 | 新建作品时按题材预填的一组资源行（系统流 / 游戏流 / 玄幻修仙 / 都市 / 西幻），清单依据附录 A 调研 |
| 备注字段 | 可选的自由文字字段（无预设），收在台账下方折叠区；兼作「系统规则备忘」（附录 A 调研：规则承诺清单是防吃书台账之一） |

## 二、需求范围

**包含**：

1. 盘点台账默认形态（新书默认，老作品无迁移负担，直接全局切换）；
2. 资源条目（增 / 删 / 改名 / 拖拽排序 / 快捷加减）与记账流水；
3. 盘点核对（账实校准，修正留痕）；
4. 资源模板与首次引导（≤3 步）；
5. 备注字段（可选、无预设、默认折叠）；
6. 现有 10 模块整体收进「进阶面板」，功能逻辑不动；
7. 窗口条幅形态改造：禁最大化 / 全屏，两档宽度（小条幅 / 中条幅，均 ≤ 屏幕工作区一半），尺寸与位置记忆；
8. 简化因「无存量用户」而不再需要的默认布局兼容兜底。

**不包含（本期不做）**：

1. 数值模块的功能改动（映射换算、货币进制、换装方案等规则一律不动）；
2. 台账资源一键升级为正式物品 / 货币模块条目（记入遗留，有反馈再做）；
3. 阈值提醒 / 余额不足预警（后续版本）；
4. AI 按正文自动盘点对账（后续版本，依赖正文解析，本期不做）；
5. 跨窗口联动机制改动（主角绑定 / 改名 / 境界广播事件照旧）；
6. 窗口停靠坞 / 边缘吸附（条幅自由摆放 + 位置记忆，不做 dock 吸附）；
7. 行囊窗口壳与断点折叠机制的重做（沿用现有三档响应式，仅按条幅宽度重校断点数值）。

## 三、方案对比与选型

| 方案 | 实现成本 | 复杂度 | 体验 | 风险 | 结论 |
|---|---|---|---|---|---|
| A. 双形态改造（盘点台账默认 + 进阶收纳） | 中 | 中 | 好 | 低 | **推荐** |
| B. 砍低频模块 | 低 | 低 | 中 | 中（误伤数值用户，不可逆） | 不采纳 |
| C. 仅加引导，不动形态 | 低 | 低 | 中 | 低 | 不采纳 |

选型理由：A 在不动数值链路的前提下，把作者真正高频的「记账盘点」提为默认态，且流水 + 盘点解决了现有 10 模块都不具备的「账实一致」问题；B 是破坏性删除且无数据支撑；C 解决不了「第一眼是 CRPG 面板」的问题。最终形态＝A 骨架 + 资源模板引导。

**演进路径**：本期 → 后续若台账使用率高：① 台账资源一键升级为正式物品 / 货币模块条目；② 阈值提醒；③ AI 按正文自动盘点对账（触发条件：作者反馈"对账太靠手动"）。

## 四、用户角色与使用场景

**角色**：网文作者（单角色），核心场景为系统流 / 玄幻等含可计数资源的题材。

| 场景 | 描述 |
|---|---|
| 主流程：随手记账 | 写到「他花了五百灵石买下丹方」→ 切到行囊 → 灵石行点 `−` 输 500 → 余额即时更新 → 关窗继续写。全程 ≤10 秒 |
| 主流程：获得资源 | 「系统奖励 1000 点数」→ 点数行点 `＋` 输 1000 → 余额更新 |
| 分支：开局建档 | 新建作品 → 第一次开行囊 → 选资源模板（或跳过）→ 台账有现成资源行 → 直接记 |
| 分支：盘点核对 | 写到中期不确定灵石还剩多少 → 查前文 → 输入实际值 → 差值自动记修正 → 继续写 |
| 分支：查流水 | 「上次花灵石是哪一章？」→ 展开资源行流水 → 按章节定位 |
| 异常：记错账 | 撤销最后一笔（流水回滚一条，余额回退） |

## 五、功能需求

### FR-01 盘点台账默认形态

行囊打开后默认展示盘点台账；CRPG 模块一律不可见，直到作者进入进阶面板。

- Given 新作品首次打开行囊，When 行囊窗口渲染完成，Then 显示盘点台账（资源模板资源行，余额全为 0），无任何 CRPG 模块内容。
- Given 作者上次停留在进阶面板，When 再次打开行囊，Then 恢复上次的形态（进阶面板），不强制回台账。

### FR-02 资源条目与资源模板

资源条目 = `{ 名称, 当前值, 类型, 单位（可选）, 上限（仅进度型、可选） }`：

- **余额型**（默认）：纯数量增减，如灵石 3,500、系统积分 12,000；
- **进度型**：当前值 / 上限展示（如「经验 500/6000」「好感度 65/100」），上限留空则只显示当前值；上限不参与记账校验（余额不变式只对当前值成立），超出上限允许但标黄提示「超上限」（剧情常写「突破上限」，不阻断）；上限随时可改（升级后上限跳变是剧情常态，不做规则联动）。

支持增 / 删 / 改名 / 改上限 / 拖拽排序。模板清单依据附录 A 调研校准：

| 模板 | 预设资源行（余额全 0；◈＝进度型） | 调研依据（附录 A） |
|---|---|---|
| 空白（默认） | 无预设，直接自建 | — |
| 系统流 | 系统积分 / 属性点 / 抽奖券 / 经验值◈ / 情绪值（或好感度）◈ | 中文系统面板标配五件套：积分商城、加点、抽奖、升级、情绪/好感收集（样本 3/5 均含） |
| 游戏流（LitRPG） | 经验值◈ / 金币 / 生命值◈ / 技能熟练度◈ / 属性点 | LitRPG 六台账中可量化四项：XP/等级、HP、货币、技能熟练度 |
| 玄幻修仙 | 灵石 / 贡献点 / 丹药 / 寿元◈ | 宗门经济三件套 + 长生流寿元（可被消耗，属余额可负场景） |
| 现代都市 | 现金 / 存款 / 系统积分 | 都市系统文以金钱类 + 积分兑换为主，无进度型标配 |
| 西幻奇幻 | 金币 / 魔晶 / 声望◈ | 游戏化西幻：货币 / 能量结晶 / 声望进度 |

（模板预填为估算值，措辞需文案定稿；同一资源可随时改型，改型不清流水。）

- Given 新作品首次打开行囊，When 显示台账，Then 提供资源模板选择（一次性、可跳过选「空白」）；选择后资源行按模板预填（进度型资源上限留空，由作者自填）。
- Given 台账已有资源，When 再次套用模板，Then 二次确认「将追加模板资源（余额 0），已有资源不变」；同名跳过。
- Given 任一资源行，When 删除，Then 需二次确认（资源连同其流水一并删除，不可恢复——依赖整文档草稿保存，无独立撤销）。
- Given 资源名重复，When 保存，Then 允许（按 id 区分），添加时非阻断提示「已有同名资源」。
- Given 资源数达 100 条，When 再添加，Then 入口置灰并提示。

### FR-03 记账与流水

- Given 任一资源行，When 点 `＋` / `−`，Then 弹出记账输入（默认 ±1，可改任意数量，`InputNumber`），确认后余额即时更新并写一条流水。
- Given 记账发生时编辑器有当前章节，When 流水落账，Then 自动带上当前章节 id（复用行囊窗口已有的 chapterId 上下文，不新增 IPC）。
- Given 任一资源行，When 展开，Then 显示该资源最近 50 条流水（估算上限）：`时间 · 章节 · ±数量 · 余额 · 备注`，新流水在顶部；超出 50 条丢弃最旧（不进回收）。
- Given 记账时可填一句备注，When 留空，Then 流水备注为空、展示跳过。
- Given 进度型资源，When 记账 / 盘点 / 撤销，Then 与余额型同构（只动当前值）；上限仅作展示与超限提示，不参与任何校验。
- Given 需要撤销，When 点流水顶部「撤销最后一笔」，Then 该资源余额回退、流水标记作废（保留记录，灰色划线展示，不计入余额累计）——不物理删除，保证账目可审计。
- Given 余额被减到负数，When 确认记账，Then 允许但余额标红提示「为负」（剧情里可能真的透支，不阻断）。

### FR-04 盘点核对

- Given 任一资源行，When 点「盘点」，Then 弹出核对输入（`InputNumber`，默认当前余额）。
- Given 输入值 ≠ 当前余额，When 确认，Then 自动生成一条 `盘点修正` 流水（差值 = 输入值 − 当前余额，备注自动填「盘点修正：输入 X」），余额更新为输入值。
- Given 输入值 = 当前余额，When 确认，Then 提示「账实一致」并记录一次盘点时间（不写流水）。
- 盘点核对的产物是普通流水，与手动加减同构——余额永远可由流水累计验证。

### FR-05 备注与规则备忘（降级，无预设）

- Given 台账底部折叠区「备注与规则备忘」，When 展开，Then 可自由添加「字段名 + 内容」的文字条目；**无任何预设字段**（身份 / 外貌 / 性格等 v1.0 预设全部移除）。
- 空态引导文案列举调研高频用法（附录 A）：「敌人战力表」「系统规则备忘」「兑换价格表」——系统流作者需维护一份「系统承诺清单」（每条写进正文的规则都是一个承诺），避免后期规则吃书。
- 交互复用 v1.1 字段行设计（增删改名、`TextArea` 自适应），入口收进折叠区，默认收起。

### FR-06 进阶面板入口

- Given 台账形态，When 点头部 `Segmented` 切「进阶」，Then 切换到进阶面板（现有模块仪表盘完整呈现，模块管理 / 单位系统等入口位置不变）。
- Given 进阶面板，When 点「台账」（Segmented），Then 切回台账。
- 形态记忆走界面偏好（`novel_pack_ui` 即改即存，不进草稿、不计入未保存改动）。

### FR-07 数据存储

- 台账作为行囊文档的新数据区段，复用现有整文档草稿与保存通道、脏标记与关闭守卫——不为台账单开第二条保存链路：

```ts
interface PackQuickcardSection {
  resources: Array<{
    id: string; name: string;
    kind: "counter" | "progress";      // counter＝余额型；progress＝进度型
    count: number;                      // 当前值
    cap?: number;                       // 仅 progress 型，可空（无上限）
    unit?: string; sortOrder: number;
  }>;
  logs: Array<{
    id: string; resourceId: string;
    kind: "init" | "adjust" | "audit" | "void";
    delta: number; balance: number;
    chapterId?: string; note?: string; ts: number;
  }>;
  fields: Array<{ id: string; name: string; value: string; sortOrder: number }>; // 备注与规则备忘
}
```

- `kind: "void"` 为撤销作废记录（不计入余额）；`balance` 冗余存储变动后余额，展示与校验双用途（校验 = 流水累计（排除 void）=== 当前 count，守卫测试断言）。
- Given 台账有未保存改动，When 关闭行囊窗口，Then 触发现有关闭守卫三通道拦截流程。
- Given 历史文档无 `quickcard` 区段，When 解析，Then 按「空台账 + 空流水 + 空备注」处理（仅防本地旧手测数据，解析不崩）。

### FR-08 首次引导

- Given 新作品首次打开行囊（台账形态），When 引导未完成过，Then 展示 ≤3 步引导：①资源行 `＋/−`「随手记账，余额即时更新」→ ②「盘点」「写到中期对一次账，防止吃书」→ ③「进阶」「属性 / 装备等数值工具收在这里」。
- Given 引导已完成或作者点跳过，When 再次打开，Then 不再出现。

### FR-09 模块布局简化（无存量兼容）

- 新书默认启用态改为：盘点台账（唯一默认可见形态）+ 进阶面板内 10 模块全部存在但**默认收起**；
- 移除 `DEFAULT_LAYOUTS` / `mergeLayouts` / `setModuleOrder` 中为旧默认态保留的兜底分支（简化后新增回归测试守卫新默认态）。

### FR-10 导出

- Given 台账有内容，When 导出，Then 现有导出通道新增「盘点台账」导出项：资源名 + 当前余额逐行输出，可选附带流水明细（复用 `pack-export` 的文本落盘通道）。

### FR-11 窗口条幅形态（v1.1 起）

行囊窗口由「桌面大窗」改为**条幅窗**：竖向长条、不占整屏、始终与编辑器同屏共存（边写边记账的核心形态）。

- 禁止最大化与全屏：`createPackWindow` 设 `maximizable: false` + `fullscreenable: false`（Electron 选项名为全小写）；`WindowHeader` 隐藏最大化按钮（其余窗口默认行为不变，经新增 prop 控制）；`forwardMaximizeState` 对 pack 窗口不再挂。
- 两档宽度（**上限均为屏幕工作区宽的一半**）：

| 档位 | 默认宽 | 可调范围 | 承载形态 |
|---|---|---|---|
| 小条幅 | 400px | 380–480px | 盘点台账（默认） |
| 中条幅 | 720px | 600px – min(880px, 工作区宽 × 0.5) | 进阶面板（模块仪表盘） |

- 高度两档同参：默认 = 工作区高 − 96px，范围 480px – 工作区高。
- 首次打开位置：主屏工作区右上，四边距 24px；此后记忆上次位置与尺寸（恢复时 clamp 进当前工作区与档位上限，防止换屏后窗口出界）。
- 形态 ↔ 档位联动：进入进阶面板时若当前为小条幅则动画过渡到中条幅；返回台账同理缩回。作者**手动拖拽调整过宽度**后以手动值为准（记忆优先于联动）。
- 拖拽缩放下限 380px（沿用），超出档位上限的拖拽被主进程 clamp。
- Given 屏幕工作区宽 < 760px（超窄屏），When 打开中条幅，Then 宽度取工作区宽 × 0.5，此时中条幅可能低于 600px：进阶面板按窄档（核心三块 + 折叠）渲染，不横向溢出。

### FR-12 断点重校（v1.1 起）

窗口宽度上限从 1080 降到 880 后，原 wide 断点 900 永不可达，须重校 `PACK_WINDOW_BREAKPOINTS`：

| 断点 | 旧值 | 新值 | 效果 |
|---|---|---|---|
| wide（双栏仪表盘） | ≥900 | ≥760 | 中条幅满档（880）可双栏；760 宽档进阶面板单栏纵向流 |
| narrow（自动折叠） | <600 | <600（不变） | 小条幅全段处于窄档，台账不受折叠策略影响（非模块） |

- 判定仍用 `contentWidth`（窗口内容区宽），守卫 `pack-layout.test.ts` 更新为新值。

## 七、业务流程与状态流转

```text
打开行囊
  ├─ 形态偏好 = 台账（默认） ─→ 盘点台账
  │     ├─ ＋/− 记账 ─→ 余额更新 + 写流水 → 标脏 → 统一保存（现有草稿通道）
  │     ├─ 盘点 ─→ 差值修正流水 → 余额=输入值
  │     ├─ 撤销最后一笔 ─→ 流水标 void → 余额回退
  │     └─ 点「进阶」 ─→ 进阶面板（10 模块仪表盘，照旧）
  └─ 形态偏好 = 进阶面板 ─→ 进阶面板 ─→ 点「台账」（Segmented）回台账
```

**形态状态机**（`PackUiPrefs.mode`）：`quickcard`（默认）↔ `advanced`，单向切换、无中间态；`mode` 未定义时按 `quickcard` 处理。

**资源余额不变式（守卫级）**：任意时刻 `resource.count === Σ logs[kind≠void].delta`，创建资源时写一条 `init` 流水（delta = 初始余额，模板预填均为 0）。

## 八、数据与埋点设计

**数据**：行囊文档新增 `quickcard` 区段（结构见 FR-07），随整文档一起走草稿 / 保存 / diff；窗口形态偏好（`mode` / `windowForm`）进 `novel_pack_ui` 即改即存。

**埋点**：当前仓库无行囊使用埋点基础。本期最小数据能力：不做新埋点，成功指标以静态验收 + 可用性自测代替；后续候选埋点：首次记账完成、盘点核对使用（本期不实施）。

## 九、权限与安全

单机单用户场景，无角色权限模型；台账内容为纯文本与整数，不涉及 PII 外发。导出走现有本地落盘。

### 11.3 拖拽排序（定稿：拖拽方案，资源行适用）

| 环节 | 规格 |
|---|---|
| 触发 | 仅**把手**可发起（pointerdown + 移动阈值 4px）；资源名与数量区不触发拖拽 |
| 拖起 | 被拖行抬升：`translateY(-2px)` + `scale(1.02)` + `var(--app-shadow-pop)`，跟手位移直接改 transform **不带 transition**；原位留 40% 透明度占位框 |
| 让位 | 其余行按落点让位，`transition: transform var(--app-t-normal) var(--app-ease-standard)`（180ms）；只动 transform/opacity |
| 落点指示 | 目标行间隙 2px 分隔线（`var(--app-primary)`），随拖动实时移动 |
| 释放 | sortOrder 重排、标脏；拖回原位不标脏；释放用 `--app-ease-spring` 归位（仅拖拽允许回弹） |
| 取消 | 拖拽中 `Esc` 或拖出列表松手 → 回弹原位，数据不变 |
| 冲突互斥 | 拖拽开始即 blur 当前编辑态与展开的流水行 |
| 键盘替代 | 资源行聚焦时 `Alt+↑/↓` 上移 / 下移；实现时在 `shortcuts/registry.ts` 校验冲突，冲突则换 `Ctrl+Alt+↑/↓` |
| 限制 | 100 资源量级全量 DOM 拖拽不虚拟化；展开流水中的条目不可拖 |

| RK-03 | 拖拽排序与输入焦点 / 展开流水冲突 | 技术 | 2 | 2 | 4 低 | 仅把手可拖 + 阈值 + 拖起 blur（11.3）；键盘 `Alt+↑/↓` 兜底 |
| RK-04 | 「进阶」入口太深，重度作者找不到原功能 | 体验 | 2 | 3 | 6 低 | 首次切进阶给一次性指引 |
| RK-05 | 测试面广（30+ 测试文件），默认态改动连锁红灯 | 进度 | 3 | 2 | 6 低 | 按 §6.6 只跑改动面，命中越界再全量；FR-09 单列守卫测试 |

## 附录 A：题材调研结论（v1.3 模板与资源模型依据）

调研范围：中文系统流面板样本（起点 / 女生网 / 17K 作者学院教程 / 网文金手指分类综述）与英文 LitRPG / GameLit 体裁指南及作者追踪方法论（Bramble《How to Keep Track of LitRPG Stats》等）。结论四条：

**A1 资源分两型，进度型占半壁江山。** 中文系统面板实例（样本 3/5）中，资源普遍是「当前值 / 上限」形式：经验 500/6000、智商 (Lv4) 888/1000 点、好感度 50/100、强化阈值阶梯（10/20/30 点档位）。纯余额型（灵石 / 积分）只是另一类。据此 v1.3 引入 `progress` 型（上限可选、超限标黄不阻断、上限随时手改不做规则联动）。

**A2 系统流标配五件套：积分 / 属性点 / 抽奖 / 经验 / 情绪（好感）值。** 金手指分类综述中「任务签到、情绪收集、加点面板、抽奖合成、商城兑换」为最主流五类，全部落到可计数资源；样本面板均含「积分 + 属性/自由属性点」，抽奖券与情绪/好感值高频出现。

**A3 游戏流（LitRPG）可量化四项：XP/等级、HP、货币、技能熟练度。** 体裁指南公认的标配要素为等级经验、属性、技能、物品、货币、任务；其中适合台账逐行记的是经验 / 生命 / 金币 / 熟练度（属性与技能明细属进阶面板既有职能，不重复做）。

**A4 「变更历史」是作者最缺、读者最爱审计的东西。** Bramble 方法论：LitRPG 读者「自带电子表格像审计师」，作者需要六本台账（数值 / 技能 / 等级经验 / 物品 / 货币 / **系统规则**）且每本都要变更历史——直接验证本方案 FR-03 流水（带章节）与 FR-04 盘点核对的核心价值；「系统规则承诺清单」则由 FR-05 备注区承接（无预设，仅空态引导文案提示）。

**落点对照**：A1 → FR-02 资源模型 / FR-07 `kind+cap` 字段 / 异常 #5a；A2·A3 → FR-02 模板清单（系统流 / 游戏流 / 玄幻 / 都市 / 西幻）；A4 → FR-03·04 已有设计 + FR-05 引导文案。
