## 一、背景与问题定位

### 1.1 真实场景

网络小说作者的构思过程是「先把故事按顺序捋出来，再回头补细节」，不是「先摆一张关系网」。写到 30 万字、80 个事件时，作者最需要回答三个问题：

1. **故事现在走到哪了**——按顺序扫一遍就知道；
2. **这一场都有谁在场**——点开事件看；某一章写着写着想起「阿箬这时应该在吧」；
3. **这个人一共出现在哪些地方**——我要检查某人物的戏份分布 / 前后是否矛盾。

### 1.2 v6.1 为什么被推翻

v6.1（自由摆放 + 一键整理）在原型阶段实测中暴露出根因级问题：

| 现象 | 根因 | v7.0 的处理 |
|---|---|---|
| 「交互只有 60% 满意，时间轴 / 轨道 / 拖拽牵强堆在一起」 | **三套位置语义并存**：时间轴刻度说「卡在哪由时间定」、轨道排布说「由泳道定」、自由拖拽说「由鼠标定」——三者对「这张卡为什么在这里」各执一词，作者每次松手都要猜系统听谁的 | **吸附格子**：位置=(泳道，槽号) 唯一语义。时间格是唯一的空间语言，拖拽 = 选格，时刻 = 槽号，堆叠 = 同槽。语义只有一套，所见即所落 |
| 自由摆放后箭头斜拉、卡片遮挡，越摆越读不出走向 | 位置与顺序解耦的代价：几何失真全靠「一键整理」兜底，而整理只重置位置、不消除堆叠，空洞照旧 | 整理语义升级为**时间线压缩**：按链序展开成连续槽（堆叠拆散、每卡一格），区域 / 时代带随成员重映射自动伸展，空洞收拢 |
| 删掉泳道后事件「迁移到默认线」违背直觉 | 作者删线常常是因为「这条线写废了」，事件应该退回待定状态而不是被塞进另一条线 | **待归类托盘**：事件允许不入线，删线后事件进托盘，作者从容重新归置 |
| 想表达「这两段之间隔了很久 / 我还没想好中间」却做不到 | v6.1 推进箭头不可删（FR-12），链是铁律 | **连线可断开/重连**（`break_before`）：断点是作者的表达自由，重连是一键操作 |

### 1.3 一句话定位

**事件是一条线上的格位，角色是格位里的注脚，时代是格位上方的段落标尺。** 格位保证顺序可读且可堆叠，注脚保证在场可查，标尺保证节奏感；跨事件的脉络不画在线上，收进右侧栏。

## 二、目标与成功指标

| 目标 | 指标 | 口径 |
|---|---|---|
| 顺序可读 | 80 个事件的同一条线，**首屏可判断前后 5 个事件** | 可用性测试：给 5 个事件标题，要求指出先后，正确率 ≥95% |
| 落格可预期 | 拖动卡片时**高亮格 = 实际落格**，松手零意外 | 可用性测试：任意拖 10 次，落格与预期不符 ≤1 次（守卫：高亮范围与命中走廊同宽同轨） |
| 在场可查 | 从「想看某事件有谁」到看全，**≤1 次点击** | 点事件卡 → 右栏出场列表可见 |
| 脉络可查 | 从「想看某角色出现在哪」到看全，**≤2 次点击** | 点卡内角色 chip → 右栏汇总（跨泳道按顺序列出） |
| 无额外维护 | 角色新增出场**1 次点击**；事件增减后时代带**自动伸缩、零手动维护** | 卡内「＋」→ 选人 → 完成；守卫断言：所有槽位变更路径都调用时代带自适应（§17） |
| 不产生脏图 | 画布上不存在跨越三个以上事件的连线；时代带**无重叠、无空洞** | 守卫断言（§17） |
| 误操作可回退 | 任意结构操作 5 秒内可单步撤销，连续 Ctrl+Z 可回退最近 50 步 | 守卫断言：撤销后槽位、区域、时代带、浮卡完全还原 |

## 三、名词与术语

| 术语 | 定义 |
|---|---|
| **事件** | 大纲的**唯一节点**：发生了什么事。字段 = 标题 + 正文 + 时间文本 + 所属泳道（可空）+ 时间槽 + 出场角色。判据：能指出「它发生在哪一刻」 |
| **时间槽（slot）** | 事件在泳道内的**位置单元**：第 N 格。横向模式一格一列、纵向模式一格一行，槽宽恒定（横向 252px / 纵向 176px 行高）。**槽号就是事件的时间序**——槽 3 的事件发生在槽 2 之后 |
| **同槽堆叠** | 两个及以上事件占据**同一槽号** = 作者声明它们发生在**同一时刻**（同一格内并排显示）。堆叠是语义（同刻），不是排版事故；一键整理会把堆叠展开成连续槽（见 §8.10） |
| **待归类** | `lane_id = NULL` 的事件：还没想好放进哪条线。显示在画布左端（纵向为底部）的**托盘**里，不占任何泳道的槽位；拖入泳道格即入线 |
| **实体** | 角色 / 势力 / 道具 / 地点 / 线索。**不是节点**，只存在于事件卡的出场区与右侧栏；跨时间持续存在，没有「发生在哪一刻」 |
| **出场（cast）** | 事件与实体的多对多关系。**同一个实体可以在任意多个事件各出现一次**；每一次出场在画布上表现为该事件卡内的一枚 chip |
| **浮卡** | 从事件卡里**拖出来的 chip**：独立小卡放在画布空白处（不占格位），用一条淡虚线牵引回所属事件。位置存在 `casts.card_x/card_y`。拖到另一张事件卡上即改挂；**拖到空白保持原归属**（v7.0 废除就近改挂） |
| **泳道 / 时间线** | 一条独立的叙事线（主线 / 副线 / 暗线）。事件单线归属，线内按槽号排列 |
| **推进链** | 同泳道内相邻槽事件之间的先后关系。**由槽号本身表达**，不建边表；箭头按槽序连成一条链，**链可在任意位置断开**（`break_before`），断开后两段各自成链 |
| **区域（zone）** | 一条泳道内**一段连续槽号区间**的标注，带名称、说明、色与样式。显示为套在成员包围盒外的一圈轻描边（对齐 XMind Boundary）；区间随成员重映射（§8.4） |
| **时代带（era）** | v7.0 新概念：横跨**全部泳道**的 rail 级色带（横向模式在画布顶部、纵向模式在最左共享列），表达「第 N~M 格属于某个时代」。槽号区间 + 随成员事件**自适应伸缩** + 空画布占位段 + 邻段让位/收拢（§8.5）。与区域的区别：era 跨线、在 rail 上、自动伸缩；zone 单线、在画布内、描边框 |
| **一键整理** | v7.0 语义：把每条泳道的链上所有事件（**含同槽堆叠**）按链序**展开成连续槽**（消空洞、拆堆叠），浮卡全部收回卡内，zone/era 区间随成员重映射自动伸展、时代带空洞收拢。**只压时间线，不改先后语义** |
| **汇总** | 右侧栏的角色视图：某实体出现在哪些事件、跨几条线、共几处引用 |

## 四、需求范围

**包含**：吸附格子时间轴（横 / 纵切换，纵向为多列并排）；事件增删改、拖拽落格（选格即定位）；同槽堆叠与堆叠展开；泳道增删改与排序（删线事件转待归类）；**待归类托盘**；事件卡内的出场角色（添加 / 移除 / 点开汇总 / 拖出浮卡 / 拖卡改挂）；同一实体跨事件多处出场；**推进链断开与重连**；一键整理（时间线压缩）；区域（槽号区间 + 成员派生 + 重映射）；**时代带（自适应伸缩 + 占位段 + 前后新增 + 让位收拢）**；右侧栏双视图（事件详情 / 角色汇总）；大纲视图（多列网格、泳道分组面板、同源）；搜索（事件 + 角色）；灵感转事件；右侧「伏笔埋设」保留；**全局撤销栈（Ctrl+Z）**；**章节关联（`outline_event_id`）与工作台 / 走向子视图 / 快捷直达（§7）**；**大纲先行（草稿态工作台 + 由此创建作品绑定）与多草稿管理（书架独立草稿分区 / 工作台草稿切换器，§7.1 / §7.6，v7.1）**。

**不包含（本期）**：**角色卡之间的自由连线**（全局脉络在右栏汇总，画布只画浮卡牵引虚线）；自由摆放（位置由格子唯一决定，无像素级偏移）；多父层级；多画布 / 多 Sheet；时间轴刻度数值（`when_text` 仍是自由文本，槽号是相对序不是绝对时间）；AI 自动生成大纲；**一个作品多套大纲方案**（一作品一份大纲由 UNIQUE 硬守，二期评估）。

## 五、方案选型

### 5.1 四种形态的取舍

| 方案 | 顺序可读 | 落格可预期 | 越写越乱 | 结论 |
|---|---|---|---|---|
| A 树形大纲（v3.0） | 好 | — | 不乱 | 否决：层级被章节绑架 |
| B 自由画布（v5.x） | **差** | 差 | **会** | 否决：无约束摆放必然失序 |
| C 自由摆放 + 一键整理（v6.1） | 好（sort 定） | **差**（三套语义打架） | 会（几何失真靠兜底） | **v7.0 否决**：原型实测 60% 不满意，位置语义不唯一 |
| **D 吸附格子（v7.0）** | **好**（槽号即顺序） | **好**（高亮格=落格） | **不会**（位置=语义，无自由偏移可乱） | **采纳** |

**v7.0 关键一招：位置即语义，格子是唯一空间语言。**

v6.1 把「顺序」和「位置」拆成两件事来保自由，代价是位置失去含义——卡在画布上的坐标不表达任何东西，作者摆乱后只有箭头还诚实。v7.0 反其道：**位置本身就是语义**。

| 维度 | 存哪 | 谁说了算 | 作者怎么改 |
|---|---|---|---|
| 时间序 | `events.slot`（槽号） | 唯一时间真相（箭头、时代带、区域、大纲列表都读它） | 拖到目标格松手；同格堆叠=声明同刻 |
| 同槽次序 | `events.sort` | 同槽堆叠卡的显示次序 | 堆叠卡内拖动换位 |
| 画布几何 | 由 `(lane_id, slot)` 派生 | 纯派生，**不存任何坐标** | 不直接改；换向/缩放自动重算 |

「自由」没有消失，而是换了出口：**同槽堆叠表达「这几场同一时刻」、断链表达「中间还没想好」、托盘表达「还没归类」、时代带空段表达「这段时代的留白」**——作者的所有推演意图都有格子语义可承载，不再需要像素级自由。

### 5.2 为什么角色不做画布节点

（沿用 v6.1 结论）用户原话：「画布上只有一张角色卡片，然后连着一堆线」。单卡多线必然交叉、单卡无法承载局部语义。**解法不是把线画得更好，而是取消线**。角色挂在事件卡里；全局看右栏。局部关系用相邻表达，全局关系用列表表达。

### 5.3 为什么顺序即推进，不建 plot 边

（沿用 v6.1 结论）同泳道内槽号即推进；跨泳道交汇是「同一时刻互相映照」，用**同槽堆叠**或事件卡文字标注表达，不画长线。删 plot 边表，推进零成本。

## 六、数据模型（大纲域七表：projects + 六表，+ 章节侧一列）

```sql
-- 0) 大纲项目（v7.1：草稿与作品大纲的统一宿主——大纲先行的数据基础）
CREATE TABLE IF NOT EXISTS novel_outline_projects (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL DEFAULT '',   -- 草稿名（如「玄幻新书构思」），空显示「未命名大纲」
  work_id    TEXT,                       -- NULL = 草稿（未绑定作品）；非空 = 已绑定作品
  sort       INTEGER NOT NULL DEFAULT 0, -- 预留手动排序；v1 草稿按 updated_at 排
  deleted_at INTEGER,                    -- 软删除标记（进回收站，30 天可恢复；恢复后 work_id 仍为 NULL）
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
-- 部分唯一索引：多份草稿（NULL）不受限；每个作品至多一份大纲（「一作品一份大纲」数据库层硬守）
CREATE UNIQUE INDEX IF NOT EXISTS idx_ol_projects_work
  ON novel_outline_projects(work_id) WHERE work_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_ol_projects_updated ON novel_outline_projects(updated_at);

-- 1) 泳道（时间线）
CREATE TABLE IF NOT EXISTS novel_outline_lanes (
  id         TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  name       TEXT NOT NULL DEFAULT '',   -- ≤20 字，空名显示「未命名时间线」
  note       TEXT NOT NULL DEFAULT '',   -- 这条线的一句话说明（≤120 字）
  sort       INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_ol_lanes_project ON novel_outline_lanes(project_id, sort);

-- 2) 事件（唯一节点；位置=(lane_id, slot)，同槽=同刻堆叠；lane_id 可空=待归类）
CREATE TABLE IF NOT EXISTS novel_outline_events (
  id           TEXT PRIMARY KEY,
  project_id   TEXT NOT NULL,
  lane_id      TEXT,                      -- NULL = 待归类（托盘）；入线后必属一条线
  slot         INTEGER NOT NULL DEFAULT 0,-- 时间槽号（≥0）；同槽=同一时刻，堆叠显示
  sort         INTEGER NOT NULL DEFAULT 0,-- 同槽内次序；顺序真相 = (slot 升序, sort 升序)
  break_before INTEGER NOT NULL DEFAULT 0,-- 1 = 与前一个事件的推进箭头断开（v7.0）
  title        TEXT NOT NULL DEFAULT '',  -- 空显示「未命名事件」
  body         TEXT NOT NULL DEFAULT '',  -- ≤20000 字
  when_text    TEXT NOT NULL DEFAULT '',  -- 自由文本时间，不做刻度；槽号才是相对序
  starred      INTEGER NOT NULL DEFAULT 0,
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  CHECK (slot >= 0),
  CHECK (break_before IN (0,1))
);
CREATE INDEX IF NOT EXISTS idx_ol_events_lane ON novel_outline_events(project_id, lane_id, slot, sort);

-- 3) 实体（角色 / 势力 / 道具 / 地点 / 线索；不是节点，没有位置）
CREATE TABLE IF NOT EXISTS novel_outline_entities (
  id         TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  type       TEXT NOT NULL DEFAULT 'char', -- char | force | item | place | clue
  name       TEXT NOT NULL DEFAULT '',
  aliases    TEXT NOT NULL DEFAULT '',     -- 逗号分隔，供搜索
  body       TEXT NOT NULL DEFAULT '',     -- ≤2000 字
  color_slot TEXT NOT NULL DEFAULT '',     -- 留空时按 type 取默认色
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_ol_entities_project ON novel_outline_entities(project_id, type);

-- 4) 出场（多对多：同一实体可在任意多个事件各出现一次）
CREATE TABLE IF NOT EXISTS novel_outline_casts (
  event_id   TEXT NOT NULL,
  entity_id  TEXT NOT NULL,
  role_label TEXT NOT NULL DEFAULT '',     -- 本场身份，如「伪装成船夫」
  sort       INTEGER NOT NULL DEFAULT 0,   -- 卡内 chip 顺序
  card_x     INTEGER,                      -- NULL=收在事件卡内的 chip；有值=浮卡位置
  card_y     INTEGER,
  PRIMARY KEY (event_id, entity_id)        -- 同一事件同一实体只能一枚 chip
);
CREATE INDEX IF NOT EXISTS idx_ol_casts_entity ON novel_outline_casts(entity_id);

-- 5) 区域（年代 / 阶段的标注：一条泳道内一段槽号区间）
CREATE TABLE IF NOT EXISTS novel_outline_zones (
  id         TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  lane_id    TEXT NOT NULL,               -- 区间必须落在同一条线内
  name       TEXT NOT NULL DEFAULT '',
  note       TEXT NOT NULL DEFAULT '',    -- ≤2000 字
  color_slot TEXT NOT NULL DEFAULT 'teal',
  shape      TEXT NOT NULL DEFAULT 'brace',   -- brace | box | pill（对齐 XMind Boundary）
  solid      INTEGER NOT NULL DEFAULT 0,      -- 0 虚线 / 1 实线
  filled     INTEGER NOT NULL DEFAULT 0,      -- 0 无底 / 1 淡底
  from_slot  INTEGER NOT NULL,            -- 起始槽号（含）
  to_slot    INTEGER NOT NULL,            -- 结束槽号（含）
  sort       INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_ol_zones_project ON novel_outline_zones(project_id, lane_id, sort);

-- 6) 时代带（v7.0 新增：跨全部泳道的 rail 级段落标尺）
CREATE TABLE IF NOT EXISTS novel_outline_eras (
  id         TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  name       TEXT NOT NULL DEFAULT '',
  note       TEXT NOT NULL DEFAULT '',    -- ≤200 字
  color_slot TEXT NOT NULL DEFAULT 'blue',
  from_slot  INTEGER NOT NULL,            -- 起始槽号（含），跨线不绑定泳道
  to_slot    INTEGER NOT NULL,            -- 结束槽号（含）
  sort       INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_ol_eras_project ON novel_outline_eras(project_id, from_slot);
```

**约束与断言**

| 约束 | 说明 | 落点 |
|---|---|---|
| `lane_id` 可空 | NULL = 待归类（托盘）；**删泳道时线内事件 `lane_id` 置 NULL**（转待归类），不再迁移默认线 | DB + handler |
| 入线事件槽号 ≥0 | 入线后 `slot` 必填且 ≥0；托盘事件 `slot` 无意义（不参与泳道渲染与时代带成员统计） | handler |
| `cast` 主键 `(event_id, entity_id)` | 同一事件同一角色只能一枚 chip | DB |
| 实体无位置字段 | 守卫断言 `novel_outline_entities` 不得出现 `x/y/lane_id/slot/sort` | 测试 |
| 区间同线 | `zone.lane_id` 必填且区间只在自己那条线上读成员；era **不绑泳道**（跨线） | handler |
| 顺序只读槽号 | 守卫断言：排序、序号、箭头、大纲列表、区域/时代带区间**只读 `(lane_id, slot, sort)`**；事件表无任何坐标列（v7.0 删除 `layout_x/y`，浮卡坐标只存在 cast 上） | 测试 |
| 浮卡必有归属 | `card_x` 非空时 `event_id` 仍必填；**宿主事件转待归类或随泳道删除时，浮卡自动收回卡内**（`card_x/y` 置 NULL），不允许「虚线连到托盘」 | handler + 测试 |
| 区域 / 时代带不存几何 | 均无 `x/y/width/height`；区域边界由成员包围盒**派生**，时代带位置由槽号区间直算；换向 / 缩放自动重算 | 测试 |
| 时代带自适应 | 守卫断言：**所有槽位变更路径**（拖放落格、新增/删除/转待归类事件、一键整理）都必须触发 era 自适应（成员 bbox 伸缩 + 邻段让位 + 空洞收拢）与 zone 区间收缩检查 | 测试 |
| 一键整理幂等 | 链已连续、无堆叠、无浮卡、zone/era 区间已贴合时，第二次整理零写入 | 测试 |
| 断点枚举 | `break_before ∈ {0,1}`；链首事件该字段无意义（渲染忽略） | DB CHECK |
| 草稿态（v7.1） | 草稿 = `novel_outline_projects.work_id IS NULL`；工作台可在**无作品上下文**打开草稿（大纲先行）；绑定后该 project 即该作品唯一大纲，六表数据经 `project_id` 归属 | DB + handler |
| 一作品一份大纲（v7.1） | `UNIQUE(project.work_id) WHERE work_id IS NOT NULL` 部分唯一索引硬守（多份草稿 NULL 不受限）；「一作品多套大纲方案」二期不进本期 | DB + 测试 |
| 绑定原子性（v7.1） | 「由此大纲创建作品」= 单事务 `INSERT novel_works` + `UPDATE novel_outline_projects SET work_id = {newWorkId}`（六表挂 project_id，数据零搬迁）；并发绑定同一作品第二份大纲触发 UNIQUE 冲突即整体回滚 | handler + 测试 |
| 软删除进回收站（v7.1） | 删草稿 / 删作品只打 `deleted_at`（复用回收站既有软删除机制，30 天保留）；六表数据**原位保留**；恢复草稿后 `work_id` 仍为 NULL（不自动绑回）；恢复作品时其 project 行同批恢复（deleted_at 同时间戳）；**彻底删除才级联物理删六表** | handler + 测试 |
| 独立性 | **六张大纲表**（按 `project_id` 隔离到 projects，projects 是大纲域唯一挂作品点）禁止出现 `chapterId` / `volumeId` / 任何指向章节域的字段；章节关联只存在于 `novel_chapters.outline_event_id`（章节域自己的列） | 守卫断言 |
| 关联完整性 | 删除事件时同事务 `UPDATE novel_chapters SET outline_event_id = NULL WHERE outline_event_id = {id}`（悬挂引用零容忍）；章节删除不动事件 | handler + 测试 |

**删除语义**

| 操作 | 影响 |
|---|---|
| 删事件 | 同时删其 `casts`（含浮卡）；zone/era 区间自适应收缩（区间空则提示删区域）；**同事务清理 `novel_chapters.outline_event_id` 引用** |
| 删实体 | 删其全部 `casts`（跨所有事件一起消失），二次确认写明「将从 N 个事件中移除」 |
| 删泳道 | 二次确认：线内 N 个事件 `lane_id` 置 NULL **转待归类**（槽号保留在内存态供重新入线参考，落库不保留语义）；线上 zone 随之删除；era 不受影响（era 跨线） |
| 删时代带 | 只删色带行，事件不受影响；占位段（UI 态，未落库）不可删 |
| 删作品 | **软删除进回收站**：作品行打 `deleted_at`，其 project 行**同批打标**（同时间戳，由作品条目代表、不单列大纲条目）；恢复作品时同批恢复；彻底删除（过期 / 手动清除）才同事务物理删六表 + UI 键 + 章节表 `outline_event_id` 置 NULL |
| 删大纲草稿（v7.1） | project 行打 `deleted_at` 进回收站（新增 `outline` 类条目，与作品 / 卷 / 章 / 要素并列，30 天可恢复）；恢复后 `work_id` 仍为 NULL（不自动绑回任何作品）；彻底删除才同事务物理删该 project 六表数据 |

## 七、信息架构与落位（v7.0 定案）

### 7.1 主入口：NovelPage 第 4 视图「大纲工作台」

**不建独立窗口**。理由：大纲与章节写作强耦合（写一章要看一次走向），独立窗口要处理双窗口只读、数据推送、焦点切换三套机制；RelationWindow 能独立是因为它几乎不依赖编辑器上下文，大纲不行。视图状态机（书架 / 编辑器 / 回收站）加一态即可，与现有机制同源。

```text
┌ 34px 拖动带 ───────────────────────────────────────────────────────────┐
├ 工具条 48px ───────────────────────────────────────────────────────────┤
│ 归墟 ▾（切换草稿/作品大纲）· 事件 8 角色 6 ｜ 时间轴/大纲 ｜ 横向/纵向 ｜ 搜索 ｜ 一键整理 ｜ ＋新事件 ｜ ⟨草稿⟩由此创建作品 │
├──────┬─────────────────────────────────────────────┬───────────────────┤
│ 托盘  │ 时间轴画布（可滚）                             │ 右侧栏 320px（可收）│
│200px │  时代 rail（横向顶部 / 纵向最左共享列）           │  事件 ｜ 角色汇总   │
│待归类 │  主线列 ｜ 副线列 ｜ 暗线列（纵向多列并排）        │                  │
│      │  ┌─ 第一纪元 ─┐                              │  [选中的事件]      │
│ 卡1  │  │ ①→② 堆叠③ │                              │  标题/泳道·第N格   │
│ 卡2  │  └───────────┘                              │  正文 / 出场角色    │
└──────┴─────────────────────────────────────────────┴───────────────────┘
```

三个区域的职责：

| 区域 | 职责 | 不做什么 |
|---|---|---|
| **托盘** | 待归类事件的暂存区；拖入泳道格即入线 | 不占槽位、不参与时代带成员统计 |
| **时间轴画布** | 表达时间序、堆叠、时代、区域；唯一可拖拽落格的地方 | 不摆像素位置、不画跨事件连线 |
| **右侧栏** | 全局汇总：事件详情 / 角色跨事件脉络 | 不是主要编辑入口（只做标题外的正文与出场增删） |

**草稿态与作品态（v7.1：大纲先行）**——大纲的宿主是 `novel_outline_projects`，`work_id IS NULL` 即**草稿态**，可先于任何作品存在（作者先在大纲修修改改，之后再创建书绑定），绑定后为**作品态**；两种形态共用同一画布：

- **草稿切换器**：工具条标题区（「归墟 ▾」）为下拉切换器——「大纲草稿」分组列出全部草稿、「作品大纲」分组列出最近 5 部已绑定作品，点击即切（切换前自动保存，沿既有保存机制）；底部「＋ 新建草稿」。上次打开的 project 记入本地偏好，无参打开时恢复。
- **草稿态徽标与建书**：标题旁「草稿」徽章 + 「由此大纲创建作品」按钮（调起书架同款两步建书弹框：书名必填 / 题材可跳过）；创建成功**留在工作台**（作品态），toast「已创建《{书名}》并绑定此大纲」。作品态无此按钮。
- **多草稿直达语义**：`Mod+Shift+O` / 无参入口在多草稿下打开**最近编辑**的草稿（不弹选择框；选别的走切换器）。

### 7.2 横向 vs 纵向

| | 横向（默认） | 纵向 |
|---|---|---|
| 结构 | 各泳道一行，槽沿 X 轴展开；时代 rail 在顶部 | **多列并排**：每泳道一列（420px），槽沿 Y 轴展开；时代 rail 为最左共享列 |
| 适合 | 事件多、想看整体节奏与断点 | 事件少、想看每一场细节与文本 |
| 一屏 | 4–6 格 | 每列 3–4 格，多列同时可见 |
| 记忆 | 按作品记忆，切回恢复 | 同左 |

### 7.3 大纲视图（同源多列网格）

按泳道分组的线性事件列表，**多列网格面板**排布（`auto-fill, minmax(360px, 1fr)`）：主线 / 副线 / 暗线 / 待归类各一面板并排成列，宽屏自动 2–4 列、窄屏回落单列；面板等高拉伸。行 = 发丝分隔线列表（编号 + 标题 + 摘要 + 出场 chips），选中行左色条。顺序与时间轴一致（同一 `(slot, sort)` 真相），只是密度与形态不同。参照 Notion 分组数据库 / Linear list view。

### 7.4 章节关联（写作侧）

| 机制 | 规则 |
|---|---|
| 数据 | `novel_chapters.outline_event_id`（可空列）。语义 =「这一章拍的是这场戏」；1 章 ↔ 1 事件，1 事件 ↔ N 章 |
| 依赖方向 | 章节域 → 大纲域单向引用；**六张大纲表对章节域零感知**，「六表无 chapterId」守卫原样通过 |
| 联动表现 | ① 事件卡显示「已拍 N 章」角标，时间轴上已拍段打勾；② 章节树行显示所拍事件标题 chip；③ AI 上下文采集器顺带读章节关联事件（FR-19） |
| 写作侧入口 | **SupportPanel 增「走向」子视图**（现有 OutlinePanel 保留章节职责）：泳道分组的线性事件列表（同源数据、280–460px 窄栏友好），点击跳大纲工作台定位该事件——写作中不离开编辑器随时扫走向 |
| 记录走向 | 章节写完保存时轻提示「拍入哪个事件？」（可跳过）；记录动作嵌进写作流，不需要专门「去维护大纲」 |

### 7.5 随时调出

| 入口 | 行为 |

| 书架顶栏「大纲工作台」（v7.1） | 常驻全局入口（首日动作）：打开工作台——有草稿开最近编辑草稿，无草稿落全新空态；作品级直达见 §7.6 |

| SupportPanel 走向列表 | 点击任意事件 → 跳工作台定位 |

### 7.6 书架页入口（v7.1：大纲先行）

书架页是大纲工作台在写作侧的门面。入口分**三层**，语义互不重叠——大纲先行后，打开工作台不再有「进谁的大纲」的歧义（顶栏 = 工作台本身，Hero / 书卡 = 某书的大纲）：

| 层 | 位置 | 语义 | 权重 |
|---|---|---|---|
| ① 全局入口 | ShelfTopBar 工具条第三颗文字按钮「大纲工作台」（与全局设定中心 / 导入书籍并列） | 打开**工作台本身**：草稿态（最近编辑草稿）或全新空态 | **P0**——大纲先行使其成为**创作侧首日动作**，与 O-10 相容（顶栏 = 首日动作区；先画大纲正是零作品新用户的第一件事） |
| ② Hero 双动作 | ContinueHero CTA 区：「继续写作」主按钮 + 「大纲 · {N} 个事件」次级按钮 | **上次写到作品**的大纲直达 | P0（写作侧高频路径，0 次寻找） |
| ③ 书卡角标 | BookCard 角标常显弱化按钮（网格右下 / 列表 trail 区）+ BookWorkMenu「打开大纲」项 | **任意作品**的大纲直达 | P1（补全覆盖层；实现约束：书卡是整卡 antd Button，button 内不嵌 button——角标为 wrapper 下兄弟元素，`onClick` stopPropagation，aria-label「打开《{书名}》的大纲」） |

**独立草稿分区（v8 形态，拍板）**：草稿卡**不进**书卡网格，在 ContinueHero 与书卡网格之间独立分区「大纲草稿」：

- 分区头：小标题 + 计数徽章（当前草稿份数）；草稿卡按**最近编辑**排序（`project.updated_at` 降序；`sort` 字段预留手动排序，v1 不做拖拽）；
- 草稿卡：虚线边框 + 「草稿」徽章区别于书卡；卡面 = 名称（空显示「未命名大纲」）+ 事件数 + 最近编辑时间；点击进工作台（该草稿）；右键（或卡角 ⋯）菜单：重命名 / 删除 / 打开工作台；
- 区尾「＋ 新建大纲草稿」虚线卡（与 NewWorkCard 同构）：点击即建（默认名可内联改名）并进工作台；
- **草稿不计入统计卡**：「累计作品 / 累计字数」等聚合按作品域统计，草稿不是作品；
- 空态：无草稿时分区只显示新建虚线卡；**零作品零草稿的新账号**，顶栏入口与新建卡常驻——先画大纲与先建作品两条路都通（回收站 / 数据安全仍在页脚不动）。

**跳转协议**：`openOutline(workId?: string)`（`useEntityJumpStore` 收口，幂等 token 同 `openRequest` 模式）——传参 = 作品态直达（经 work 反查 project）；不传 = 草稿态（恢复上次 project 或最近编辑草稿）。视图状态机新增第 4 态 `outline`：类型用 `NovelView = GuideView | "outline"`（Tour 归属类型 `GuideView` 不动，引导系统零改动）；WindowHeader 徽标随视图显示「大纲」。

**O-10 关系声明**：回收站 / 数据安全仍是「出事才会用」的页脚元操作，不回退；大纲是高频主流程 + 首日动作，进顶栏合法；统计卡 / 页脚一律不改。

## 八、展示规则与关键交互

### 8.1 事件卡

```text
┌──────────────────────────┐
│ ③ 庙明第七个名字          │  ← 序号（链内计数）+ 标题
│ 前六个都划掉了，第七个位置  │  ← 摘要 2 行（超出省略）
│ 空着，边缘是新的。         │
│ 第七次倒灌前夜 · 3 个出场   │  ← 时间文本 + 出场数
│ ─────────────────────    │
│ ●沈砚 ●阿箬 +1    ＋      │  ← 出场 chip（超宽折叠）+ 添加（固定角色行右端）
└──────────────────────────┘
```

| 要素 | 规则 |
|---|---|
| 尺寸 | 横向宽固定 200（格宽 252，两侧留 26px 呼吸位，不戳出区域框）；纵向宽 200。**统一最小高 150**（空卡与满卡等高；`.ev` flex 纵向布局、出场区 `flex:1` 撑满） |
| 序号 | 链内按 `(slot, sort)` 计数；堆叠卡共用一个槽号、按 sort 编次序 |
| 摘要 | `body` 前两行，超出省略；空正文显示占位「写点什么…」 |
| 时间 | `when_text` 自由文本；留空显示「未标时间」 |
| 出场 chip | 高 24，圆头像（类型色）+ 名字；超宽折叠为「+N」 |
| 「＋」钮 | 固定在角色行**右端**（与 chip 同基线）；空卡角色区垂直居中余白，＋钮位置不变 |
| 选中 | 2px 主色描边 + 外发光 |
| 搜索命中 | 外发光改为警示色弱底；未命中整卡淡化 32% |
| 位置 | **由 `(lane_id, slot)` 唯一决定**，无任何自由偏移；同槽多卡在格内并排（纵向槽内横向排、横向槽内纵向排） |
| 已拍角标 | 章节关联非空时显示「已拍 N 章」小角标（§7.4） |

### 8.2 出场 chip 与浮卡

| 规则 | 说明 |
|---|---|
| **副本不是复制品** | 同一实体在多个事件各一枚 chip，共享实体资料，各自可带本场身份（`role_label`） |
| **副本之间不连线** | 画布层不渲染任何 chip→chip 的线；守卫断言 |
| **可拖出成浮卡** | 拖 chip 出事件卡（>4px）→ 变浮卡落在松手处；出场数不变；淡虚线牵引回所属事件 |
| **浮卡拖到另一事件卡** | 松手在卡上 → 该出场**改挂到那一场**；目标已有同实体则提示「这个事件里已经有一张了」并复位 |
| **浮卡拖到空白** | **位置记住、归属不变**（v7.0：废除 200px 就近改挂——实测误改挂率高，作者拖到空白多数是想「暂放」，不是想「换场」） |
| **宿主变更兜底** | 宿主事件转待归类 / 随泳道删除 → 浮卡自动收回卡内（角色不丢，虚线不连托盘） |
| **浮卡可收回** | 浮卡「↩」收回成 chip；「×」移除出场；一键整理批量收回 |
| **联动高亮** | 点任一 chip → 右栏角色汇总 + 画布同实体 chip 全部高亮 2px 环 |
| **移除只影响本处** | chip × 只从当前事件移除，提示「它还在其他 N 个事件里」+ 撤销 |
| **同一事件去重** | 同一事件同一实体只能一枚 chip |
| **数量无上限** | 一个事件挂 20 个角色允许（折叠「+N」）；一个角色出现在 200 个事件允许 |

### 8.3 推进链与断点

| 项 | 规则 |
|---|---|
| 推进箭头 | 同泳道相邻槽事件之间恒有箭头（主色 2px + 实心三角）；**按 `(slot, sort)` 槽序连成链** |
| 可断开 | 右键箭头或事件 →「断开与上一段的连线」→ `break_before=1`；断点处显示断链标记（chainBreak），两段各自成链、序号各自计数 |
| 可重连 | 断点右键「接回上一段」或一键整理后手动重连；`break_before=0` |
| 同槽短箭头 | 同槽堆叠卡之间画**短直箭头**（表示「同刻连续动作」），不画贝塞尔大弧 |
| 直角肘 | 相邻槽两卡横向错位 >24px 且格间空隙 <64px 时，箭头走**圆角直角肘**（沿格间空隙平移再插入），避免斜穿其他卡片 |
| 三种线互不相同 | 推进：主色 2px 实线 + 箭头 ｜ 浮卡牵引：类型色 1px 虚线 + 端点圆点 ｜ 区域边界：虚线描边、无方向 |
| 跨线关联 | 事件卡「↔ 渡口那夜」文字标注（指向另一事件 id）；点击跳转并脉冲；**不画线**。同一时刻的跨线映照优先用**同槽堆叠**表达（跨线同槽 = 两条线在同一格交汇） |

### 8.4 区域（zone）

| 项 | 规则 |
|---|---|
| 定义 | 一条泳道内**一段槽号区间** `[from_slot, to_slot]`，带名称、说明、色、样式；渲染时按当前落在区间内的事件取**成员包围盒**画描边 |
| v7.0 语义 | 区域框住的是「这组事件」：一键整理 / 拖动重排后，区间按**移动前记录的成员**的新槽号重映射（min/max）——整理前后框住的永远是同一组卡 |
| 收包 | band 宽 / 高按成员实际占位收包（横向收高度、纵向收宽度），不画整行 / 整列大框；卡边到 band 边 ≥6px 呼吸位 |
| 标签 | **统一「标题在上、描述在下」**：横向挂边界上沿外侧；纵向统一挂 band **右上外侧**（v7.0 纯几何判定：右侧可用 ≥110px 一律右置，永不遮挡上一行卡片） |
| 样式 | `brace`（默认，四边完整虚线）/ `box` / `pill`；虚 / 实线；无 / 淡底；7 色板 |
| 改名 / 说明 | 双击标签就地改名；右键样式菜单（形状 / 线条 / 填充 / 7 色 / 删除） |
| 「包一个区域」 | 右栏「＋ 包一个区域」→ 待选态 → 点同线另一事件成区（起点取槽号靠前者）；跨线拦截保持待选 |
| 空区间 | 区间内 0 事件 → 提示「这段区间已空」并建议删除 |
| 层叠 | 不嵌套；重叠时按 sort 后画的在上 |

### 8.5 时代带（era，v7.0 新增核心）

| 项 | 规则 |
|---|---|
| 定义 | 横跨全部泳道的 rail 级色带：横向模式在画布顶部（46px 统一高度）、纵向模式在最左共享列（宽 88px）。表达「第 N~M 格属于某时代」 |
| 随成员自适应 | **所有槽位变更路径**（拖放落格、增删事件、转待归类、一键整理）后自动重算：事件落在某段覆盖之外 → 就近段自动变长纳入；边缘事件被删 / 移走 → 段自动收缩；空段保留手动拉伸范围（拉伸空段 = 划定领地） |
| 邻段让位 | 手动拉伸 / 自适应伸展压到相邻段 → 相邻段**保跨度整体平移**让位（`resolveEraOverlaps`，重叠级联向右传播） |
| 空洞收拢 | 段收缩 / 删除后留下的空槽：**任何路径都收拢**（v7.0 拍板：手动也不留空档）——按左右次序逐段平移到紧贴前一段，只消空洞、不改各段宽度与先后 |
| 占位段 | 空画布（无任何 era）自动播种一个置灰「未命名时代」占位段（默认 3 格）：随事件增加自适应变长；改名或新增其他段后「转正」为普通段；**占位段是 UI 态不落库、不可删除**（画布底座） |
| 新增段 | 右键任意段 →「＋ 前方新增时间段」「＋ 后方新增时间段」：新段默认 1 格、紧贴创建、自动进改名，随后拖边拉伸；邻段自动让位、不留空档 |
| 展示 | 色带块：淡底（≤34% 混合）+ 24% 描边 + 顶部 3px 色条（纵向） / 左 3px 色条（横向）+ 名称（600 字重）+ 「N 事件」小字（**不展示格数**，v8.2 拍板）；占位段灰阶虚线 + 操作提示小字 |
| 拖边调范围 | 拖左右（纵上下）边缘调区间：拉长推邻段、缩短吸拢邻段，实时生效 |
| 与 zone 的分工 | era = 时间节奏的段落标尺（跨线、rail、自动）；zone = 叙事结构的分组框（单线、画布内、成员派生）。同一槽号可同时被 era 与 zone 覆盖，互不干扰 |

### 8.6 右侧栏 · 事件视图 / 角色视图

（沿用 v6.1 §8.5/8.6 全部规则）选中事件显示标题、泳道 · 第 N 格、时间、正文、出场列表、＋添加、＋包一个区域；角色视图显示汇总三数（出场事件 / 画布引用 / 涉及线）、「出现在」列表（泳道 → 槽序排列、点击定位）、「未使用」分组。

### 8.7 交互流程

**主路径：新建并排好一段**

1. 工具条「＋ 新事件」→ 追加到当前泳道链尾（新槽）并选中；
2. 双击标题就地改名；右栏写正文；
3. 卡内「＋」→ 选角色 → 生成 chip；
4. 想调时间序：拖卡片到目标格（高亮格实时显示）→ 松手落格；
5. 想表达「同一时刻」：把卡拖到已占格 → 同槽堆叠；
6. 想表达「中间还没想好」：右键断开与上一段的连线。

**分支：把角色拖到另一场去**

1. 拖 chip 出卡 → 浮卡跟手；
2. 拖到目标卡（主色外环）→ 松手改挂；拖到空白 → 暂放（归属不变）；
3. 「↩」或一键整理收回。

**分支：删掉一条写废的线**

1. 右键列头 → 删除 → 二次确认「N 个事件会转入待归类」；
2. 事件进托盘，浮卡自动收回卡内；era 不受影响。

**分支：写完一章拍入事件**

1. 章节保存 → 轻提示「拍入哪个事件？」；
2. 选事件 → `novel_chapters.outline_event_id` 落值；
3. 时间轴该事件卡出现「已拍 1 章」角标；SupportPanel 走向列表该行显示章节 chip。

### 8.8 拖拽（v7.0 只剩两种，别搞混）

**手势分工**：

| 手势 | 改什么 | 反馈 |
|---|---|---|
| 拖**事件卡** | `lane_id` + `slot`（落格即定位；托盘事件拖入线 = 入线） | 命中走廊高亮（**与命中判定同宽同轨**，所见即所落）；列内 slots 上方区域 = 第 0 格（插顶一次到位）；命中走廊外松手吸回原格，**绝不过户邻列**（纵向命中走廊 = 列左缘 +300px，防列间空隙误命中） |
| 拖**角色 chip / 浮卡** | `casts.event_id`（改挂）/ `casts.card_x/y`（浮卡位置） | 被拖 chip 淡出 32%；目标卡主色描边 |

| 项 | 规则 |
|---|---|
| 拖出阈值 | 位移 >4px 才算拖动 |
| 同槽堆叠换位 | 堆叠卡在格内拖动换 `sort` |
| 取消 | `Esc` / 拖出窗口松手（`buttons===0` 检测）/ 窗口失焦 → 吸回原格零写入 |
| 键盘等价 | 选中事件 `Ctrl+←/→`（横向）或 `Ctrl+↑/↓`（纵向）移动一格；`Ctrl+Shift+←/→` 跨线移动 |
| 触控 | 长按 300ms 进入拖动 |

### 8.10 一键整理（v7.0：时间线压缩）

| 项 | 规则 |
|---|---|
| 做什么 | ① 每条泳道链上所有事件（**含同槽堆叠**）按链序**展开成连续槽**——纵向排成一列 / 横向排成一行，每卡一格，空洞消除、堆叠拆散；② 所有浮卡收回卡内；③ zone 区间按移动前成员的新槽号重映射（自动伸展 / 收缩）；④ era 区间同样重映射 + 邻段让位 + **空洞收拢**（首尾相接） |
| 不做什么 | 不改变链上先后次序（slot 单调不减映射）、不删任何出场、不删任何区域 / 时代带行 |
| 语义 | 整理 = 「把我零散写的时间线压成紧凑的一段」；堆叠是临时草稿态，展开是定稿态 |
| 幂等 | 链已连续、无堆叠、无浮卡、区间已贴合 → 第二次零写入 |
| 撤销 | toast「撤销」+ Ctrl+Z 双通道；槽位、区域、时代带、浮卡完整还原 |
| 动画 | FLIP：从旧位置动画飞回格位（`--app-t-normal` + `--app-ease-emphasized`） |
| 提示 | 「已整理：N 格事件展开排布，M 张角色卡收回卡内」（为 0 的项不提） |

### 8.11 撤销栈（v7.0 新增）

| 项 | 规则 |
|---|---|
| 触发 | `Ctrl+Z`（macOS `Cmd+Z`）；输入框聚焦时不响应 |
| 覆盖 | 全部结构操作：拖放落格、增 / 删 / 转待归类事件、删泳道、一键整理、增删时代带、拖边拉伸、改范围、era/zone 改名、区域样式与删除、断开 / 重连连线、章节拍入 / 取消拍入 |
| 实现 | 深度快照栈（上限 50 步，满丢最旧）；每步快照 = 六表相关数据 + UI 选中态 |
| 并存 | toast 上的单次「撤销」按钮保留（5s 窗口），与 Ctrl+Z 独立计数 |

## 十、功能需求

| 编号 | 需求 | 规则 / 验收（Given-When-Then） |
|---|---|---|
| **FR-01** | **吸附格子时间轴** | 每条泳道内事件按 `(slot, sort)` 排列；横向槽沿 X 轴、纵向多列槽沿 Y 轴。Given 一条线 6 事件，When 切横/纵，Then 顺序与槽号完全一致 |

## 十四、快捷键与无障碍

| 键 | 场景 | 行为 |
|---|---|---|
| `↑ ↓ ← →` | 选中事件 | 同线内按槽移动 |
| `Enter` | 选中事件 | 右栏聚焦正文 |
| `N` | 任意 | 新建事件 |
| `Ctrl+←/→`（横）/ `Ctrl+↑/↓`（纵） | 选中事件 | 移动一格（等价拖拽落格） |
| `Ctrl+Shift+←/→` | 选中事件 | 跨线移动到同槽 |
| `Ctrl+Shift+L` | 任意 | 一键整理 |
| `Ctrl+F` | 任意 | 聚焦搜索 |
| `Ctrl+Z` | 任意 | 撤销上一步（50 步） |
| `Esc` | 任意 | 取消拖拽 / 关浮层 / 清搜索 |
| `Delete` | 选中事件 | 删除（二次确认） |
| `[` `]` | 选中 chip | 同实体出场间跳转 |
| `H` / `V` | 任意 | 切横向 / 纵向 |
| `Mod+Shift+O` | 窗口级（编辑器 / 书架） | 直达大纲工作台：编辑器 = 当前作品；书架 = 最近编辑草稿；回收站页不注册 |

**无障碍**：时间轴 `role="list"` + `aria-setsize/posinset`（按槽号）；堆叠卡 `aria-label="{槽号}、{次序}、{标题}、{N} 个出场"`；时代带 `role="group"` + `aria-label="时代 {名称}，第 {from+1} 到 {to+1} 格"`；`prefers-reduced-motion` 关闭 FLIP；对比度 ≥4.5:1。

**落地红线（AGENTS §6.1）**：原型中的 10/11px 小字（era 小字、大纲 chip、行号）落地时**全部 ≥12px**，弱化改用颜色 / 字重表达，不用字号。

| B9 帮助手册 | `guide` 词条 | 大纲工作台 / 时代带 / 托盘 / 断链 / 拍入 / **书架大纲入口与草稿** 7 词条（缺了 `guide-doc.test.ts` 会红） |

**守卫断言**（同级 `*.test.ts`）

1. 独立性：六表按 `project_id` 隔离且无 `chapterId`/`volumeId`（projects 是大纲域唯一挂作品点）；大纲组件不 import 章节 store；
2. 顺序只读槽号：排序 / 序号 / 箭头 / 大纲列表 / 区间只读 `(lane_id, slot, sort)`；事件表无坐标列；
3. 无长连线：画布无 chip→chip、浮卡→浮卡边；浮卡牵引线**不指向托盘事件**（源码断言 + DOM 无对应 path）；
4. 同一事件同一实体唯一（DB 主键 + handler 拦截）；
5. 实体无 `lane_id`/`slot`；
6. zone 区间同线；era 不绑泳道；
7. era 自适应全覆盖：所有槽位变更路径（落格 / 增删 / 转待归类 / 整理）都触发 era 计算（枚举调用点断言）；
8. era 无重叠无空洞：任何写路径后 `resolveEraOverlaps + compactEras` 已执行（对拍断言）；
9. 一键整理幂等且不改链序（slot 映射单调不减）；
10. 删事件级联清 `novel_chapters.outline_event_id`（同事务）；
11. 浮卡宿主转待归类 / 删线时 `card_x/y` 置 NULL；
12. `docs-index-guard` 篇数同步；
13. 草稿生命周期（v7.1）：删草稿 / 删作品为软删除（六表原位保留），恢复草稿后 `work_id` 仍 NULL，恢复作品同批恢复其 project（`deleted_at` 同时间戳）；恢复后六表数据完整性对拍；
14. 一作品一份大纲与统计隔离（v7.1）：并发绑定同一作品第二份大纲被 `idx_ol_projects_work` UNIQUE 拒绝且事务回滚；草稿不计入「累计作品 / 字数」等作品域统计聚合。
