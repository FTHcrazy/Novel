## 一、背景与问题定位

1. **现状**：大纲板骨架由真实卷章派生（`NovelPage/types.ts` 硬规则），作品的未来无落点；
2. **v1.0–v3.0 的方向性错误**：所有版本都在设计「大纲与章节怎么绑定」——而真实写作里**一个走向节点覆盖十几章**，且大纲是作者改得最频繁的东西，任何绑定都会让高频修改变成同步负担；
3. **v4.0 的正确内核（保留）**：大纲 = 独立的走向引导层，与章节零绑定；成因 = 零散点子拼凑出脉络；
4. **v4.0/v4.1 的表达力不足（v5.0 要解决的）**：卡片墙只有「一层分组 + 平铺」，作者真实的思考是**网状的**——一段设定会牵动三条剧情线，一个点子会同时属于「背景」和「伏笔」，两个节点之间还有跨线的因果。这些关系在单层卡片墙里只能塞进正文，写的人自己都找不回来。所以要换成**能画关系、能分线、能分层**的画布；
5. **v5.0 定位（三原则）**：
   - **独立**：大纲域与章节域互不引用，章节怎么建是大纲之外的事；
   - **网状**：节点之间可自由连线，层级只表达从属，不表达章节顺序；
   - **多线并行**：一个故事本来就有主线 / 副线 / 人物线，允许多条线并行铺开，而不是压成一条队列。

## 三、名词与术语

| 术语 | 定义 |
|---|---|
| 大纲域 | 独立的走向引导层：书纲 + 分类 + 时间线 + 节点 + 关联，落库于新表，与章节域零绑定 |
| 节点 | 大纲的最小单位：标题（可空）+ 自由长文描述 + 可选分类 + 可选时间线 + 可选父节点 |
| 书纲节点 | 画布上的虚拟中心节点（id 固定为保留字 `book`）：渲染 `novel_outline_docs.content` 的四段书纲（定位 / 核心冲突 / 主线走向 / 结局预期），本身不是 `novel_outline_nodes` 记录 |
| 父子层级 | 节点间的从属关系（`parent_id`，**单父多根**）：决定大纲视图的缩进与折叠范围；**不映射卷章** |
| 关联（relation） | 任意两节点之间的自由连线：可带标签（「因果」「伏笔」「呼应」）、可跨分支跨泳道；与父子层级互不影响 |
| 分类 | 节点「是什么」：预设 设定 / 背景 / 人物 / 势力 / 事件 / 线索 / 道具 / 其他，可改名、改色、增删；**不强制**，可空（未分类） |
| 时间线（泳道） | 节点「在哪条线上」：每作品可建多条（默认「主线」），节点单线归属 + 线内顺序；时间线排布下即一条横向泳道 |
| 画布 | 无限平面：自由排布（默认，位置由作者摆放）或时间线排布（泳道横排，位置由线内顺序决定） |
| 大纲视图 | 同一份数据的结构化呈现：按父子层级缩进，列表 / 卡片两档密度 |
| 未连接 | 既无父节点、也无子节点、也无任何关联的节点（等同 v4.0「点子区」语义，但改为由关系计算得出，不再是一个固定容器） |
| 折叠 | 节点收起其全部下级子树的显示（数据与边不变）；折叠节点显示 `+N` 徽标 |
| 散点 | 无父节点的根级节点（可有子节点）：画布上可自由摆放，不对应任何容器 |
| 孤儿边 | `from_id` 或 `to_id` 指向已不存在节点的关联记录（启动时清理并记日志） |
| 聚光 | 搜索命中时，非命中节点与边降低不透明度（20%），命中项高亮的定位手法 |
| 伏笔埋设 | 右侧支撑面板页名（原「大纲」改名）：既有大纲板功能全保留（卷章骨架 + 章梗概行内编辑 + 伏笔增删改回收） |
| 章梗概 | `novel_chapters.outline_note`（既有字段）：章节属性，随章节树展示——**不是大纲的一部分** |

## 四、需求范围

**包含**：大纲域新表（书纲 / 分类 / 时间线 / 节点 / 关联）；**导图式画布**（自由排布 + 时间线排布、平移缩放、多选、吸附）；**多层父子层级**（单父多根、折叠、循环阻断）；**节点分类体系**（预设 8 类 + 自建、不强制、分类色）；**自由连线**（任意两节点、标签、样式、删除、关联高亮）；**多条时间线**（泳道增删改排序、节点归属与线内顺序）；**左栏三维度分组导航**（分类 / 时间线 / 未连接）；**搜索定位**（结果列表 + 画布聚光 + 逐条跳转）；**大纲视图同源**（缩进列表 + 卡片密度）；书纲四段；灵感「转为节点」；右侧面板改名「伏笔埋设」；AI 上下文接入节点与关联。

**不包含（本期不做）**：

- **多画布 / 多 Sheet** —— 一作品一画布；「把内容分开放」由多条时间线 + 折叠承担（理由：跨泳道的关联若被画布切开就看不见，多 Sheet 会破坏网状表达）；
- **图片 / 附件 / 手绘 / 便签贴纸** —— 本期纯文本节点（图会迅速变成第二编辑器）；
- **富文本 / 表格 / 公式** —— 同上；
- **自动生成结构（AI 归纳散点成树）** —— 后续池；本期 AI 只读（喂走向与关联给生成用）；
- **固定导图模板（鱼骨 / 矩阵 / 组织架构等结构套版）** —— 后续池；本期只提供「整理布局」一种自动排布；
- **多值标签体系** —— 与分类的容器语义冲突，跨界用关联线表达（§5.6）；
- **大纲进度对照（节点 vs 章节进度）** —— 与零绑定冲突，记遗留池（作者手点的进度徽标，非自动绑定）；
- **脉络定稿 / 版本快照 / 协作 / 多端同步** —— 桌面单机不适用；
- **导出为图片 / 大纲文档** —— 后续池；本期只支持「复制为缩进纯文本」。

## 五、同类产品调研

### 5.1 范围与方法

- **样本**：① 思维导图类（Xmind、MindMeister）：层级 + 自由连线的成熟范式；② 画布类（Obsidian Canvas、Milanote、Heptabase）：无根自由布局与「未归属材料」；③ 时间线类（Plottr）：多线并行的泳道模型；④ 写作类（Scrivener、橙瓜码字）：写作场景下的目录与状态；⑤ 文档类（飞书、Notion）：导航、搜索、层级一致性。
- **观察维度**：层级展开收起、分组与导航、节点状态、搜索定位、拖拽与连线、多线并行、进度 / 高亮反馈。
- **方法**：官方用户指南、帮助中心、版本说明与公开评测交叉比对（2026-11 检索）。
- **局限**：未做逐帧实测与版本级差核对；只取交互范式，不复制任何产品的文案、视觉与专有结构命名。

### 5.3 七类交互的方案优劣与取舍

**① 层级：深树 vs 单层 vs 无层级**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 任意深父子 | Xmind、Scrivener | 从属关系真实存在（设定 → 人物 → 关系） | 表达力最强；折叠即降噪；键盘缩进效率高 | 层级易失控；改父级连带移动整棵子树；深树占空间 |
| B. 单层分组 | v4.1 卡片墙、Plottr | 只做归类不做从属 | 结构稳定、误操作成本低 | 表达不了从属，作者会把从属写进正文 |
| C. 无层级 | Canvas / Milanote | 探索期、素材墙 | 零约束 | 数量一多即失控，无法「收起来看主干」 |

**取舍（→ C1'）**：**A 深树可达，但默认不长**——层级由作者自建（`Tab` 建子级、`Shift+Tab` 提升），不预设深度、不自动生成；用「折叠」「仅显示该分支」控噪。与 v4.0 否决的「树形大纲」区别见 §5.5。

**② 分类与分组维度**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 单一分组维度 | v4.1 卡片墙 | 结构简单 | 心智负担最低 | 一个节点只能待在一处（「这条既是背景也是伏笔」无处安放） |
| B. 多值标签 | Xmind Label、Scrivener | 一词多义 | 一个节点可多标签，筛选灵活 | 纯标签没有「容器」感，无法在左栏形成稳定分组树 |
| C. 多正交维度（分类 + 泳道 + 层级） | Plottr（行 + 章节 + 标签） | 元素同时有多种归属语义 | 三套维度各管一件事，互不挤占 | 概念多，需要清晰的左栏与视觉编码 |

**取舍（→ C2'）**：**C**。分类管「是什么」（单值，可空）、时间线管「在哪条线」（单值，可空）、父子管「从属」（单值，可空）。三者正交，左栏可切维度查看。**不做多值标签**（会与分类的容器感打架，跨界用关联线 + 标签文字表达）。

**③ 自由连线**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 只允许树形边 | Scrivener、橙瓜 | 结构即文档 | 简单、可自动布局 | 跨分支关系无处表达（伏笔跨三条线是常态） |
| B. 额外关系线（标签 + 样式） | Xmind 关联、Canvas 连线 | 网状思考 | 表达力强，可与树共存 | 边一多会糊成一团，需要高亮与筛选 |
| C. 自由画布连线（无树） | Canvas / Milanote | 素材关系 | 最自由 | 没有主干，写长文时找不到「主线」 |

**取舍（→ C3'）**：**B**。父子用 `parent_id`（保证大纲视图可渲染、单父可校验），跨分支关系用独立边表（可带标签、可删除）。可读性靠三件事兜底：悬停高亮相邻边、点击边可选中编辑、关系线默认虚线细线（不与父子主干抢视觉）。

**④ 多时间线**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 单队列（一条线） | 卡片墙 | 线性叙事 | 简单 | 副线 / 人物线只能混在主线里 |
| B. 行 = 剧情线（泳道） | Plottr | 多线并行规划 | 一屏看多线，跨线对照直观；节点归属唯一 | 节点只能在一行；泳道多了纵向吃紧 |
| C. 多画布 / 多 Sheet | Xmind、Heptabase | 内容量太大要分文件 | 每个画布可独立聚焦 | 跨画布关系看不见，需来回切换 |

**取舍（→ C4'）**：**B**。泳道横排、节点单线归属、跨线用关联线表达。不做 C，理由：写作时最需要看的恰恰是「两条线在哪里交汇」，切开就丢了。

**⑤ 搜索定位**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 就地过滤（隐藏不命中） | v4.1 卡片墙、Binder 搜索 | 列表型界面 | 结果集中 | **画布上会打断连线上下文**，剩余节点位置失去参照 |
| B. 结果列表 + 画布聚光 | 导图类工具、Canvas 搜索 | 空间型界面 | 保留全局结构，命中位置可感知 | 命中多时需逐个跳 |
| C. 仅高亮不跳转 | 部分白板 | 快速确认 | 无干扰 | 命中在视口外就找不到 |

**取舍（→ C5'）**：**B**，并明确推翻 v4.1 的「就地过滤」——形态从列表变画布后，隐藏节点会摧毁空间语义，这是形态变化驱动的必要修正（§5.6）。

**⑥ 拖拽**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 自由拖动 + 子树跟随 | Xmind / Canvas | 空间表达 | 直觉、可整体搬移 | 位置不表达顺序，需另设顺序真相 |
| B. 拖拽改层级（拖到节点上变子级） | Xmind、Scrivener | 树形整理 | 一步完成归类 | 落点语义模糊，易误操作 |
| C. 拖拽改顺序（列表内） | 大纲视图、Plottr | 顺序表达 | 顺序即位置，无歧义 | 表达不了空间关系 |

**取舍（→ C6'）**：**A + C 分工，B 显式化**。画布自由拖动只改位置（子树跟随），**不改顺序语义**；顺序真相只有 `sort`（大纲 / 时间线视图里拖拽改的就是它）；改父子必须走显式动作（`Alt+拖` / 右键「设为子节点」/ 大纲缩进），不做「随手拖上去就变子级」。

**⑦ 状态与高亮**

| 方案 | 代表 | 适用 | 优势 | 劣势 |
|---|---|---|---|---|
| A. 业务状态 + 进度 + 字数 | Scrivener、橙瓜 | 对象与正文 1:1 | 客观可量化 | 零绑定下无法派生，手填必荒废 |
| B. 分类色 + 标记 | Xmind、Plottr | 视觉分类 | 一眼分辨类型 | 颜色滥用后失去区分度 |
| C. 关系高亮 / 命中聚光 / 焦点环 | 导图类通用 | 网状结构 | 解决「这条牵到哪」，成本低 | 只是过程反馈，不回答「做到哪」 |

**取舍（→ C7'）**：**B + C**，A 进遗留池。分类色是**唯一固定的颜色语义**（8 个色槽，不允许自选任意色，避免花掉）；高亮只做过程反馈（相邻边、搜索聚光、拖拽落点、焦点环、保存回执）。

### 5.4 决策映射

| 编号 | 结论 | 决策 | 落点 |
|---|---|---|---|
| C1' | 深树表达力强但需控噪 | 作者自建多层父子 + 折叠 + 仅显示分支，默认不生成 | §8.4 / FR-26 |
| C2' | 单一分组维度装不下「既是背景又是伏笔」 | 分类 / 时间线 / 父子三套正交维度；不做多值标签 | §7.3 / FR-11 / FR-25 |
| C3' | 跨分支关系是写作刚需 | 父子用 `parent_id`，跨分支用关联边表（可带标签） | §6 / FR-15 / FR-27 |
| C4' | 多线并行要看交汇，不能切开 | 泳道式多时间线，节点单线归属，跨线用关联边 | §8.5 / FR-19 / FR-29 |
| C5' | 画布上隐藏节点会毁掉空间语义 | 搜索改为「结果列表 + 聚光」，不做就地过滤 | §8.6 / FR-16 / FR-21 |
| C6' | 位置与顺序是两回事 | 位置 ≠ 顺序；`sort` 是顺序唯一真相，提供「按位置整理顺序」 | §8.7 / FR-23 / FR-30 |
| C7' | 进度在零绑定下不可信 | 分类色固定 8 槽；高亮只做过程反馈；进度进遗留池 | §8.9 / RK-01 |
| C8' | 折叠 / 缩放是个人视角 | 折叠、视口、排布模式存 `novel_config`，不进内容表 | §6.5 / FR-19 |
| C9' | 大图渲染瓶颈在节点与边数量 | DOM 节点 + 边按量切换 SVG/Canvas + 视口裁剪 + LOD | §15 / FR-20 |
| C10' | 误操作代价决定作者敢不敢改 | 移动 / 连线 / 删除 / 改父级全可撤销（20 步） | §8.8 / FR-21 |
| C11' | 层级必须可校验，否则大纲渲染会崩 | 单父约束 + 循环阻断 + 删除时子树处置二选一 | §9.2 / FR-26 |
| C12' | 分类与泳道是容器，删容器不能删内容 | 删分类 / 泳道 → 成员降级为空值，不级联删 | §11.3 / FR-25 / FR-29 |
| C13' | 导图与大纲必须同源，否则两处打架 | 同一数据两套渲染；切换保留选中与折叠 | §8.10 / FR-32 |
| C14' | 顺序需要可校对、可带走 | 大纲视图支持复制为缩进纯文本（行尾标注关联），只读导出不落库 | §8.10 / FR-32 |

### 5.5 与 v4.0「否决树形大纲」的关系（评审必读）

v4.0 否决的是**「大纲 = 作品树的镜像」**：节点与卷 / 章 1:1 绑定、节点顺序即章节顺序、改大纲就等于改目录。那套模型的问题不在「有层级」，而在「层级被章节绑架」。

v5.0 的层级是**作者自己的图**：父子由作者随手建立，没有任何自动映射；同一节点可以覆盖十几章；节点删了章节不受影响；章节建了节点不增长。所以它满足 v4.0 的零绑定铁律，只是把表达力从「平铺」提升到「可分层 + 可连线 + 可多线并行」。

一句话区分：**v4.0 否决的是「章节的树」，v5.0 要的是「作者自己的图」。**

### 5.6 明确不采纳

| 做法 | 出处 | 不采纳理由 |
|---|---|---|
| 多画布 / 多 Sheet | Xmind、Heptabase | 跨泳道交汇会看不见（C4'） |
| 多值标签体系 | Xmind Label | 与分类的容器语义冲突；跨界用关联线（C2'） |
| 自动布局为默认 | Xmind | 会打乱作者的空间记忆；只在显式点「整理布局」时排（C6'） |
| 拖到节点上即变子级 | Xmind | 落点歧义 + 易误操作；改父子须显式动作（C6'） |
| 进度 / 字数 / 完成度 | Scrivener、橙瓜 | 零绑定下只能手填（C7'） |
| 图片 / 附件 / 富文本 | Milanote、Xmind | 会把画布变成第二编辑器，本期纯文本 |
| 搜索即隐藏非命中 | v4.1 卡片墙 | 画布形态下会破坏空间语义（C5'） |

## 六、数据模型（大纲域新建，章节域零改动）

```sql
-- 1) 书纲（每作品一份，惰性补建）：四段自由文本 + 分类字典
CREATE TABLE IF NOT EXISTS novel_outline_docs (
  id         TEXT PRIMARY KEY,
  work_id    TEXT NOT NULL UNIQUE,
  content    TEXT NOT NULL DEFAULT '{}',
  -- JSON: { book: {position, conflict, mainline, ending},
  --         bookPos: {x, y},
  --         categories: [{id, name, colorSlot, sort}] }
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 2) 时间线 / 泳道
CREATE TABLE IF NOT EXISTS novel_outline_lanes (
  id         TEXT PRIMARY KEY,
  work_id    TEXT NOT NULL,
  name       TEXT NOT NULL DEFAULT '',    -- 空名显示「未命名时间线」
  note       TEXT NOT NULL DEFAULT '',    -- 这条线的背景说明（≤500 字），时间线排布下显示在泳道名下方
  color_slot INTEGER NOT NULL DEFAULT 0,  -- 0-7，复用分类色槽
  sort       INTEGER NOT NULL DEFAULT 0,  -- 泳道纵向顺序
  collapsed  INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_novel_outline_lanes_work ON novel_outline_lanes(work_id, sort);

-- 3) 节点（灵感 / 点子 / 走向）
CREATE TABLE IF NOT EXISTS novel_outline_nodes (
  id          TEXT PRIMARY KEY,          -- 保留字 'book' 禁用（守卫断言）
  work_id     TEXT NOT NULL,
  parent_id   TEXT,                      -- 单父；NULL = 根（散点 / 多根之一）。禁自引用、禁成环
  lane_id     TEXT,                      -- 所属时间线；NULL = 未入线
  category_id TEXT,                      -- 分类 id（存 docs.content.categories 内）；NULL = 未分类
  title       TEXT NOT NULL DEFAULT '',  -- 可空，占位「未命名节点」
  body        TEXT NOT NULL DEFAULT '',  -- 自由长文，≤20000 字符
  x           REAL NOT NULL DEFAULT 0,   -- 自由排布坐标（逻辑坐标，非屏幕像素）
  y           REAL NOT NULL DEFAULT 0,
  collapsed   INTEGER NOT NULL DEFAULT 0,-- 折叠子树
  starred     INTEGER NOT NULL DEFAULT 0,-- 作者手点「重点」
  sort        INTEGER NOT NULL DEFAULT 0,-- 同级顺序（大纲与时间线排布的唯一顺序真相）
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_novel_outline_nodes_work ON novel_outline_nodes(work_id);
CREATE INDEX IF NOT EXISTS idx_novel_outline_nodes_parent ON novel_outline_nodes(work_id, parent_id, sort);
CREATE INDEX IF NOT EXISTS idx_novel_outline_nodes_lane ON novel_outline_nodes(work_id, lane_id, sort);
CREATE INDEX IF NOT EXISTS idx_novel_outline_nodes_cat ON novel_outline_nodes(work_id, category_id);

-- 4) 连线（三层语义：剧情推进 / 关联；父子走 parent_id 不在此表）
CREATE TABLE IF NOT EXISTS novel_outline_edges (
  id         TEXT PRIMARY KEY,
  work_id    TEXT NOT NULL,
  from_id    TEXT NOT NULL,             -- 起点节点 id
  to_id      TEXT NOT NULL,             -- 终点节点 id
  kind       TEXT NOT NULL DEFAULT 'relation', -- plot(剧情推进) | relation(关联)
  label      TEXT NOT NULL DEFAULT '',  -- 关系描述，≤30 字（plot 通常为空）
  style      TEXT NOT NULL DEFAULT 'dashed', -- dashed | solid（仅 relation 可切；plot 恒实线）
  seq        INTEGER NOT NULL DEFAULT 0, -- 仅 plot：本段在叙事链上的序位，用于「按顺序走一遍」
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_novel_outline_edges_work ON novel_outline_edges(work_id);
CREATE INDEX IF NOT EXISTS idx_novel_outline_edges_from ON novel_outline_edges(work_id, from_id);
CREATE INDEX IF NOT EXISTS idx_novel_outline_edges_to ON novel_outline_edges(work_id, to_id);
CREATE INDEX IF NOT EXISTS idx_novel_outline_edges_kind ON novel_outline_edges(work_id, kind);

-- 5) 区域（作者自划的年代 / 背景分区，带说明；不参与父子与时间线）
CREATE TABLE IF NOT EXISTS novel_outline_zones (
  id         TEXT PRIMARY KEY,
  work_id    TEXT NOT NULL,
  name       TEXT NOT NULL DEFAULT '',   -- ≤20 字，空名显示「未命名区域」
  note       TEXT NOT NULL DEFAULT '',   -- 背景说明，多行 ≤2000 字
  color_slot TEXT NOT NULL DEFAULT 'teal', -- accent 名（teal/rose/blue/amber/purple/green/orange）
  x          REAL NOT NULL DEFAULT 0,    -- 自由排布下的矩形（逻辑坐标）
  y          REAL NOT NULL DEFAULT 0,
  w          REAL NOT NULL DEFAULT 320,
  h          REAL NOT NULL DEFAULT 220,
  sort       INTEGER NOT NULL DEFAULT 0, -- 同名叠放时的绘制顺序
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_novel_outline_zones_work ON novel_outline_zones(work_id, sort);

-- 6) 区域成员（多对多；成员按几何包含自动维护，也可手动锁定）
CREATE TABLE IF NOT EXISTS novel_outline_zone_members (
  zone_id TEXT NOT NULL,
  node_id TEXT NOT NULL,
  PRIMARY KEY (zone_id, node_id)
);
```

| 设计选择 | 理由 |
|---|---|
| 父子用 `parent_id` 而非「层级边表」 | 单父天然可校验（一行只有一个父）；大纲视图 O(n) 渲染；循环检测只需向上遍历。若父子也进边表，多父会让树退化成图，大纲无处缩进 |
| 关联用独立边表 | 多对多无法塞进节点行；边要带标签与样式；删除节点时需按 from/to 精确清理 |
| 连线用 `kind` 而非再建一张表 | 剧情推进与关联的**结构完全同构**（from / to / 可选标签），差的只是渲染语言与语义。分表会让「同一对节点从关联改成推进」变成跨表搬迁；同表加 `kind` 只需改一个字段。`seq` 仅对 plot 有意义，relation 恒 0 |
| 父子不进边表，但 plot 与父子可共存 | 一条边同时是「从属」和「顺序」时（沈砚 → 替师父刻名），渲染**让位给 plot**（结构信息由折叠/大纲承担，不叠两条线）；数据上仍两条都存，切换视图不丢语义 |
| 区域单表 + 成员关联表 | 区域要独立改名、改说明、改色、调矩形，且一个节点可被多个区域覆盖（如「第七次倒灌」同时在「碑林线」与「主线中段」）；把 `zone_id` 塞进节点会退化成单归属 |
| 分类字典存 JSON 而非建表 | 分类是低频变更的小字典（≤20 条），与书纲同生命周期；为 8 个默认名建第五张表不划算 |
| 时间线建表而非 JSON | 泳道要独立排序、改名、着色、折叠，且被 `lane_id` 引用，需要稳定 id 与索引 |
| `x/y` 与 `sort` 并存 | 位置表达空间关系，`sort` 表达阅读顺序，二者不可互相推导（§8.7） |
| 书纲不建节点行 | 四段结构固定、每作品唯一，放 `docs.content` 更简单；画布上以保留 id `book` 的虚拟节点渲染 |

| 既有物 | 处置 | 理由 |
|---|---|---|
| `novel_volumes` / `novel_chapters`（含 `outline_note`）/ `novel_outline_entries` / `novel_snapshots` | **零改动** | 章节域自治；右面板与章节树继续服务写作导航 |
| 存量作品 | **天然兼容**（章节域未动 + 大纲域空表起点）；若 v4.1 已上线，需一次轻量迁移：卡片 → 节点（`kind='card'` 转 node）、分组 → 泳道（`kind='group'` 转 lane） | 迁移脚本幂等、可重入 |
| 删除作品 | 同事务级联删大纲域四表 + `novel_config` 视图键 | 不残留孤儿 |

**独立性铁律**：大纲域**六表**禁止出现 `chapterId` / `volumeId` / 任何指向章节域的字段；章节域禁止反向引用大纲；由守卫断言（§17）。

### 6.5 视图状态与排序规则

视图状态存 `novel_config` 单键 `outline_ui:{workId}`（与关系图窗口画布记忆同模式）：

```jsonc
{
  "view": "canvas",            // canvas | outline
  "arrange": "free",           // free | timeline（仅 canvas）
  "zoom": 1,
  "pan": { "x": 0, "y": 0 },
  "sidebar": { "dimension": "category", "collapsed": false, "collapsedKeys": [] },
  "outlineDensity": "list",    // list | card
  "lastNodeId": "n_x",
  "searchScope": "title"       // title | all（规模降级记忆）
}
```

| 规则 | 说明 |
|---|---|
| 折叠的真相 | 节点折叠存 `nodes.collapsed`（随节点走）；泳道折叠存 `lanes.collapsed`；左栏分组折叠存 UI 状态 |
| `sort` 步长 | 同级新建 = 相邻两条中间值，初始 1024；间隔 <2 时对该父级下全部子节点重写为 1024、2048…（单事务） |
| 位置与顺序解耦 | 自由画布拖动**只写 x/y，不写 sort**；时间线 / 大纲拖拽**写 sort，不写 x/y**；「按位置整理顺序」是一次显式操作，把当前视觉阅读序（先 y 后 x）写回 `sort` |
| 坐标范围 | `|x|,|y| ≤ 1e6`；越界归一化到当前视口中心并记日志 |
| 稳定排序 | 排序键追加 `created_at`、`id` 兜底，避免同值抖动 |

### 7.2 三种呈现（同一数据）

| 呈现 | 入口 | 位置来源 | 适用 |
|---|---|---|---|
| 画布 · 自由排布（默认） | 视图 = 画布 + 排布 = 自由 | `x/y`（作者摆放） | 推演、看整体关系、摆布局 |
| 画布 · 时间线排布 | 排布 = 时间线 | `lane.sort` + 节点 `sort` | 对照多条线、排顺序、找交汇 |
| 大纲视图 | 视图 = 大纲 | `parent_id` + `sort` | 写长文、校对结构、快速整理 |

切换规则：切视图保留选中节点与折叠态；切排布保留缩放与中心点；**任何在一种呈现里做的修改，其它两种立即反映**（同源渲染，无「同步」动作、无冲突提示）。

### 7.3 左栏四维度

| 维度 | 树结构 | 点击 | 拖拽 |
|---|---|---|---|
| 分类（默认） | 分类 → 该分类下的根级节点（可展开子树，缩进 12/级） | 定位到画布并选中（脉冲 1.5s） | 把节点拖到分类项 = 改分类（仅该节点） |
| 时间线 | 泳道 → 线内节点（按 `sort`） | 同上；点泳道名 = 画布滚到该泳道 | 拖到泳道 = 改归属并追加到线尾 |
| **区域** | 区域 → 区域内节点（按几何归属，§8.11） | 同上；双击组头 = 编辑背景说明 | 拖到区域项 = 仅改位置到该区域内（不改分类与时间线） |
| 未连接 | 单组：无父无子无边（含 plot）的节点 | 同上 | 拖出仅改位置 |

规则：左栏条目显示「标题 + 分类色点」；条目 >200 启动虚拟滚动；左栏**不支持拖拽排序**（排序在画布与大纲做，避免两处语义打架）；维度切换与各自折叠态记忆在 UI 状态。

## 八、展示规则与关键交互

### 8.1 节点视觉

```text
┌──────────────────────────────┐
│▌ 标题（1 行，超出省略）    ★ │  ← 左侧 3px 分类色条；★ 重点（手点）
│  描述摘要 2 行（超出省略）    │
│  ┄ 3 条关联 · 4 个子节点      │  ← 脚注：关联数 / 子节点数
└──────────────────────────────┘
        ○  ← 折叠按钮（有子节点时）：− 展开 / +N 收起
```

| 要素 | 规则 |
|---|---|
| 尺寸 | 宽固定 200；高自适应（标题 + 摘要 2 行 ≈ 88；无正文 ≈ 56；折叠态 44） |
| 分类色 | 左侧 3px 竖条 + 左栏色点；8 个色槽由主题语义令牌映射（组件内 `--ol-cat-1..8` 局部变量，**禁止硬编码色值**，铁律 5） |
| 未分类 | 无色条（`--app-border` 中性描边），不显示色点 |
| 空白节点 | 虚线描边 + 标题占位「未命名节点」+ 摘要占位「写点什么…」 |
| 重点 | 右上实心星 + 描边升一档 |
| 折叠 | 右下 `+N` 胶囊；点击展开 |
| 选中 | 2px 主色描边 + 外发光 2px（不填充，避免盖住分类色） |
| 悬停 | 描边升一档 + 四向锚点浮现 |
| 保存失败 | 右上红色三角角标 + tooltip「未保存，点击重试」 |

### 8.2 分类体系

| 规则 | 说明 |
|---|---|
| 预设 | 设定 / 背景 / 人物 / 势力 / 事件 / 线索 / 道具 / 其他（8 个，各占一个色槽） |
| 可空 | 新建节点默认「未分类」；不选也能写、能连线、能进时间线 |
| 自建 | 可新增（≤20 个）、改名（≤12 字）、改色槽、排序、删除 |
| 删除分类 | 成员降级「未分类」，不删节点（C12'）；二次确认写明数量 |
| 快捷指定 | 选中节点按 `1–8` 设为对应色槽分类，`0` 清除；多选时批量生效 |
| 色槽复用 | 一个色槽可被多个分类复用（允许重复，靠名称区分），不做「一分类一唯一色」强约束 |

### 8.3 连线三层（结构 / 推进 / 关联）

**为什么必须分三层**：「沈砚 → 替师父刻名 → 听见自己的名字」是**故事怎么走**；「沈砚 ↔ 阿箬：同门」是**这两人什么关系**。两者都是「两点之间一条线」，但作者看图时问的问题完全不同——前者是「接下来发生什么」，后者是「这跟那个有没有关系」。用同一根虚线表示，主线就淹在关系网里了。

| 层 | 语义 | 数据来源 | 视觉语言 |
|---|---|---|---|
| **父子** | 从属（谁在谁下面） | `nodes.parent_id` | 细实线 1.5px，中性色 `--app-border`，**无箭头**；折叠时整枝不画 |
| **剧情推进** | 叙事顺序（然后呢） | `edges.kind='plot'` | 主色 `--app-primary` 实线 **2.5px** + **实心三角大箭头（10px）** + 起点 3px 圆点；无标签 |
| **关联** | 关系 / 指示（谁和谁有关） | `edges.kind='relation'` | `--app-border-strong` **虚线 5/4** + 细箭头（7px）+ 中点标签 |

| 项 | 规则 |
|---|---|
| 三者互斥呈现 | 同一对节点同时有父子与 plot 时**只画 plot**（结构信息由折叠与大纲承担），避免两线重叠导致「线在中途分叉又合上」 |
| 颜色 | 只有 plot 用主色。**任何层都不按分类着色**——分类色已在节点左条上，线再着色会让交叉处无法辨认 |
| 标签 | 仅 relation 有；中点，≤30 字，超出省略 + 悬停全显；无标签时显示小圆点（点击可输入） |
| 创建 | 拖右侧锚点落目标 = 关联；**按住 `Shift` 拖 = 剧情推进**（拖拽中提示条实时显示当前将建哪一类）；或选中 1–2 个节点按 `Ctrl+L`（关联）/ `Ctrl+Shift+L`（推进） |
| 箭头 | 三角按**末段切线角度**现场绘制（不走 SVG marker），保证箭头永远贴着曲线方向；线端回缩半个箭头长度，线不吃进箭头里 |
| 规则 | 禁自环；同向**同 kind** 重复合并并提示；反向允许但提示「已有反向关联，仍要建立？」；单节点关联软上限 30（超出提示但允许）；**plot 额外约束**：同一节点可有多条入 / 出（分叉剧情），不做「链唯一」强校验 |
| 相邻高亮 | 选中 / 悬停节点时，相邻边与对端节点高亮，其余降到 40%；plot 高亮额外加 6px 半透明光晕（宽度差是唯一的「重要性」信号，不加动效） |
| 折叠节点的隐藏边 | 被折叠的子节点不绘制其边；折叠徽标 tooltip 显示「含 3 条连线」 |
| 删除 | 点边选中 → `Delete` 或右键「删除」；无二次确认（可撤销） |
| 顺序视图联动 | 大纲视图里 plot 显示为 `→ 剧情推进 · {对端}` 的主色 chip，relation 显示为 `↔ {标签}` 的灰 chip（§8.10） |

### 8.4 层级与折叠

| 规则 | 说明 |
|---|---|
| 建子级 | 选中 `Tab`（新建子节点）；右键「设为子节点」；`Alt+拖` 节点到目标 |
| 提升 | `Shift+Tab` 提升一级（挂到祖父下）；已是根则无操作 |
| 单父 | 一个节点只有一个父；改父级 = 从原父移出并挂到新父末尾（子树跟随，可撤销） |
| 多根 | 允许任意多个根（散点、各线起点）；不强制「必须有中心」 |
| 循环阻断 | 目标是自身或自身后代时拒绝，提示「会让层级绕回来」（§11.3 #3） |
| 折叠 | 节点右侧 `+N` / `−`；`Ctrl+/` 折叠或展开其全部子级；`Ctrl+Shift+/` 全部折叠 / 展开 |
| 仅显示该分支 | `Ctrl+Shift+F`：除当前子树外全部淡化到 15%（不隐藏，保留空间记忆）；再按恢复 |
| 折叠不影响数据 | 只影响渲染；子节点、关联、顺序全部保留 |
| 深度 | 不设上限；深度 >6 时子节点改向右下阶梯排布，避免长链出屏 |

### 8.5 多时间线（泳道）

| 规则 | 说明 |
|---|---|
| 默认 | 每作品一条「主线」，惰性创建（首次切时间线排布时） |
| 增删改 | ≤12 条；可改名（≤20 字）、排序（拖泳道头）、折叠、删除（二次确认：节点降级为未入线，不删） |
| 归属 | 节点单线归属；`lane_id` 为空 = 未入线（画布底部「未入线」区，不可排序） |
| 线内顺序 | 由 `sort` 决定，横向从左到右；泳道内拖拽换位改 `sort` |
| 跨线 | 用关联线表达（跨泳道绘制贝塞尔曲线，可关「显示跨线关联」） |
| 泳道带 | 背景浅色横带 + 左侧泳道名（滚动画布时吸左固定）+ 节点计数 |
| 时间轴刻度 | 不画日期轴；泳道内可选显示序号（1、2、3…），仅表示顺序不表示章节 |
| 交汇 | 同一节点不能同属两条线；「两条线在同一处交汇」用「A 关联 B」表达，以两节点间的连线呈现 |
| **泳道说明** | 每条线可写背景说明（≤500 字）：泳道名下方两行，超出省略 + 悬停全显；双击泳道名可编辑。时间线排布下的「区域说明」就落在这里——自由排布用区域框，时间线排布用泳道说明，同一诉求两个视图各自的载体 |

### 8.6 搜索与定位

| 步骤 | 行为 |
|---|---|
| 1 | `Ctrl+F` 聚焦左栏搜索框；`Ctrl+K` 打开结果浮层（同一搜索实例） |
| 2 | 输入 ≥1 字符，300ms 防抖；范围 = 节点标题 / 正文 / 分类名 / 泳道名 / 关联标签 / 书纲四段 |
| 3 | 结果浮层每条显示「分类色点 + 标题 + 命中片段（前后各 8 字，命中词加粗黄底）+ 路径（分类 / 时间线）」 |
| 4 | 选中结果 → 画布居中该节点（缩放不低于 80%）+ 1.5s 脉冲 + **聚光**（非命中 20%） |
| 5 | `Enter` 下一条，`Shift+Enter` 上一条；`Esc` 退出聚光并恢复原视口与选中 |
| 6 | 聚光期间仍可编辑（不锁画布）；点空白处退出聚光 |
| 7 | 规模降级 | 节点 >1000 时默认只搜「标题 + 分类名 + 泳道名 + 关联标签」，勾选「含正文（较慢）」才全文检索 |

**为何不用 v4.1 的就地过滤**：画布的空间布局本身承载语义（谁在谁旁边、哪条线更靠上），隐藏节点会让剩余节点失去参照，等于把作者的记忆打乱。列表可以过滤，画布只能聚光。

### 8.7 位置与顺序（两套真相）

| 动作 | 写入 | 不写 |
|---|---|---|
| 自由画布拖动节点 | `x/y`（子树整体位移） | `sort`、`parent_id` |
| `Alt+拖` 节点 | `x/y` + `parent_id`（改父级） | `sort`（落在新父末尾） |
| 时间线排布拖动 | `sort`、必要时 `lane_id` | `x/y` |
| 大纲视图拖动 | `sort`、必要时 `parent_id` | `x/y` |
| 「按位置整理顺序」 | `sort`（按视觉阅读序：先 y 后 x，同层级内） | `x/y` |

**为什么解耦**：空间位置是「想摆在哪儿」，顺序是「读下去是什么次序」。硬绑在一起会导致「我只想挪开看一眼，结果大纲顺序全乱了」——这是导图类工具最常见的不满来源。解耦的代价是需要一个显式的「按位置整理顺序」，收益是两套表达互不破坏。

### 8.8 撤销与重做

| 项 | 规则 |
|---|---|
| 覆盖 | 移动（位置 / 顺序 / 跨线 / 改父级）、建删节点、建删关联、改分类、改标题与正文（2s 合并）、删除分类 / 泳道 |
| 不覆盖 | 折叠、缩放平移、搜索、视图切换（视角，不入栈） |
| 栈深 | 20 步，会话内、按作品隔离 |
| 反馈 | 删除类操作 toast 带 5s「撤销」；其它仅 `Ctrl+Z` 可回退，无 toast |

### 8.9 高亮与反馈预算

| 反馈 | 触发 | 形式 |
|---|---|---|
| 分类识别 | 常驻 | 左色条 + 左栏色点（唯一固定颜色语义） |
| 相邻关系 | 悬停 / 选中节点 | 相邻边与对端高亮，其余 40% |
| 落点 | 拖拽中 | 插入线（排序）/ 目标节点描边（改父级）/ 泳道带高亮（换线） |
| 搜索命中 | 搜索 | 结果列表高亮 + 画布聚光 20% |
| 焦点 | 键盘 | 2px 焦点环（外扩 2px） |
| 保存 | 停止输入后 | 右上角 ✓ 1.2s 淡出（失败为红色角标） |
| 撤销 | 操作后 | toast（仅删除类） |

明确不做：进度条、完成度百分比、字数进度、节点呼吸动效、连线循环流动动画（>300 节点会拖慢且干扰阅读）。

### 8.10 同源切换与导出

| 规则 | 说明 |
|---|---|
| 切换 | 画布 ⇄ 大纲：保留选中节点、折叠态、搜索词；缩放与平移各自记忆 |
| 大纲视图结构 | 按 `parent_id` 递归 + `sort`；列表密度 = 缩进 16/级 + 行高 32；卡片密度 = v4.1 卡片（宽 240、摘要 3 行） |
| 顺序提示 | 若大纲顺序与画布位置明显不符，顶部提示「大纲顺序与画布位置不一致」+「按位置整理顺序」（每作品提示一次，可忽略） |
| 复制为文本 | `Ctrl+Shift+C`：按当前层级复制为缩进纯文本（Tab 缩进，plot 以 `→` 标注顺序、relation 以 `→ {标签}` 标注行尾），仅写剪贴板，不落库 |

### 8.11 区域（年代 / 背景分区）

**解决什么**：「这段故事发生在哪、那阵子的世界是什么样的」既不是节点、也不是时间线——它是**背景板**。作者需要一块能框住一片节点、写上说明、随手挪走的东西。XMind 用「边界 + 概要」表达同一诉求，我们合并成一个对象：**区域 = 矩形 + 标题 + 说明**。

| 项 | 规则 |
|---|---|
| 创建 | 工具条「框选区域」，或画布空白处 `Shift+拖` 直接拉框；落在空白处默认尺寸 320×220 |
| 视觉 | 虚线 1px 边框（`--app-accent-{slot}`）+ 同色 8% 弱底；标题为左上外挂的实色胶囊（高 24，圆角 pill，白字）；说明文字在框内左上，最多 4 行（超出省略，tooltip 全显） |
| 说明 | 多行文本 ≤2000 字；空态占位「双击添加背景说明…」；改说明走标题条双击或左栏「区域」维度双击组头 |
| 挪动 | **只能拖标题条**（框内其余区域 `pointer-events: none`，保证节点照常可点、可拖、可新建）；拖动时**成员节点与区域一起位移**，不破坏相对位置 |
| 成员归属 | 按**几何包含**自动判定（节点中心落在矩形内即成员），拖动结束后重算并落库；不做「手动加成员」的常规入口，避免与几何不一致的两套真相 |
| 层级 | 区域恒在**最底层**（节点、连线之上不可见其遮挡）；区域之间不嵌套（本期），重叠允许但绘制按 `sort` |
| 改色 | 右键标题条 → 7 个 accent 色点（复用语义色，不自造色相） |
| 删除 | 右键「删除区域」→ 二次确认「删除「{名称}」？其中 {N} 个节点会保留，只是不再属于任何区域」 |
| 与视图关系 | **仅在「自由排布」显示**；切「时间线排布」自动隐藏（泳道本身即区域，两者并存会语义打架），切回恢复 |
| 与左栏关系 | 左栏维度第三档「区域」按区域分组列出成员，点击定位；维度切换记忆在 UI 状态 |
| 搜索 | 区域名与说明进搜索范围（§8.6），命中区域的说明时结果条目路径显示「{区域名} · 背景说明」 |

**明确不做**：区域嵌套、区域自动换色、区域参与布局算法、区域导出为图片。理由：边界模糊的能力会让「这节点到底属于哪块」变成日常争议，而背景板的价值在**读**不在**算**。

### 8.12 布局与连线路由

**两个必须分开解决的问题**：① 节点摆在哪里（布局）；② 线怎么走（路由）。混在一起做，任何一处调整都会毁掉另一处。

#### 8.12.1 布局（节点位置）

| 场景 | 算法 | 保证 |
|---|---|---|
| 「整理布局」 | **树形 tidy 布局**：递归测子树高度 → 子节点在父右侧 300px 处垂直排布 → 父节点垂直居中于子树 → 多根按高度贪心分列（2 列均衡） | 同层零重叠（子树高度已计入间距 132）；兄弟顺序 = `sort` |
| 新建节点 | 落点做**碰撞检测**：与任一节点矩形重叠 >8px 则下移 132px，最多试探 40 次 | 手点一处不会压在别人身上 |
| `Tab` 建子级 | 父右侧 300，纵向 = 已有兄弟数 × 132 | 不压已有兄弟 |
| 时间线排布 | 泳道内按 `sort` 水平排布，间距 262（卡宽 200 + 间隙 62） | 线内不重叠 |
| 大纲视图 | 无坐标概念，纯 `parent_id` + `sort` | — |

**为什么不引入力导向**：力导向的落点是随机的，作者第二次打开图和第一次看到的布局不一样——空间记忆是画布的核心资产。确定性布局 + 手摆才是导图该有的样子。

#### 8.12.2 路由（连线怎么走）

| 规则 | 做法 |
|---|---|
| **动态锚点** | 比较两节点中心的 `dx/dy`：`|dx| ≥ |dy|` 走水平（右侧出 / 左侧入，或反之），否则走垂直（下出 / 上入）。**这是消除「反向绕线」的关键**——固定「右出左入」会让目标在左边的线先向右跑再折回来 |
| 控制点 | 沿出边法线方向延长 `k = clamp(dist × 0.42, 42, 190)`，三次贝塞尔；两端切线方向可控，箭头角度自然 |
| 箭头 | 按末段切线现场画三角，线端回缩 9px（plot）/ 7px（relation） |
| 标签避让 | 标签取曲线中点、上移 8px，加 4px 同底色描边（`paint-order: stroke`）保证压线可读 |
| 多层并存 | 同一对节点的 plot 优先，父子让位（§8.3） |
| 交叉 | **不做事后避障**（运行时 A* 避障会让线抖动且成本高）。交叉由布局阶段控制：树形布局天然无交叉；跨分支关联必然交叉，靠「选中高亮相邻 + 其余降透明」读，而不是靠绕开 |

**落地补充**：节点 >300 时连线层切 Canvas（§8.9 / FR-20），但**路由算法不变**——Canvas 只是把同样的贝塞尔换成一次性绘制，不做视觉差异。

### 8.13 画布框架选型

**结论：`@xyflow/react`（React Flow v12）为主，`elkjs` 负责布局计算；X6 列为备选。** 判定依据是我们自己的约束，不是社区热度。

| 维度 | React Flow | AntV X6 | tldraw | 选择 |
|---|---|---|---|---|
| 节点即 React 组件 | ✅ 原生 | ⚠️ 需 `ReactShape` 包装，事件/状态经实例桥接 | ✅ 但为 canvas 渲染 | **RF 胜**：节点卡里有星级、折叠徽标、分类条、行内编辑，全是 React 状态 |
| 与 Zustand / antd 的关系 | 受控 `nodes/edges`，天然受控 | 命令式实例（`graph.addNode`），需双向同步 | 自有 store，迁移成本高 | **RF 胜**：我们的 store 已是唯一真相源 |
| 主题化（`--app-*` 变量） | 节点/边都是 DOM/SVG，CSS 变量直通 | 节点 HTML 可，边为 SVG 亦可，但样式要穿透实例 | canvas 绘制，需逐色传参 | **RF 胜**：换肤零成本 |
| 连线路由 | 需自研（本方案 §8.12.2 已给算法） | **内置 manhattan + avoid 避障** | 无连线语义 | **X6 在此项胜**，但我们不做运行时避障（§8.12.2），差距被抵消 |
| 分组 / 区域 | 子流程 `parentId` 或自绘底层 | 内置 group | 内置 frame | 两者都够；我们自绘区域（§8.11），不依赖框架 |
| 大图性能 | 视口裁剪 + 只渲染可见；>1000 节点需自己上 LOD | 更强（Canvas 渲染模式） | 强 | **X6 略胜**，但我们的量级（300–2000）RF 可覆盖 |
| 包体 / 维护 | ~50KB，活跃 | ~400KB，活跃 | ~300KB | **RF 胜** |
| 生态与文档 | 极好 | 好（中文佳） | 好 | 平 |

**若未来「运行时避障」成为硬需求**（例如作者明确要求线不许穿过卡片），迁移点是 `renderEdges` 一个模块：数据模型（from/to/kind/label）与框架无关，换 X6 只重写渲染层，不动表结构。

**布局库**：`elkjs`（layered 算法，支持端口约束与节点间距），仅在「整理布局」时跑一次（≤200ms/300 节点），结果写回 `x/y`。**不用 dagre**：dagre 已停止维护，且不支持端口约束。

**明确不用**：`tldraw`（白板向，无节点连线语义，做关系图要重造轮子）；`konva/pixi` 纯自绘（等于自己写一遍 React Flow）；`G6`（图分析向，编辑交互弱）。

## 九、状态设计

### 9.1 节点状态机

**状态集合**：`空白` / `草稿` / `重点`（叠加）/ `折叠`（叠加）/ `保存中` / `保存失败` / `外部更新` / `已删除`

| 状态 | 进入条件 | 视觉 | 允许操作 | 迁出 |
|---|---|---|---|---|
| 空白 | `title='' AND body=''` | 虚线描边 + 双占位 | 全部 | 输入任一字符 → 草稿 |
| 草稿 | 标题或正文非空 | 实线 + 摘要 | 全部 | 清空 → 空白 |
| 重点 | 点星标 | 实心星 + 描边升档 | 取消 | 再点 → 取消 |
| 折叠 | 有子节点且点折叠 | `+N` 胶囊，子树与子树关联边隐藏 | 展开、拖动（子树跟随）、删除 | 再点 / `Ctrl+/` → 展开 |
| 保存中 | 停止输入 600ms 后发起 | 默认不可见；>1500ms 显示「保存中…」 | 继续编辑 | 回执成功 → 草稿；超时 → 保存失败 |
| 保存失败 | 重试 2 次仍失败 | 红色角标 + 「未保存 · 重试」 | 点击重试 | 成功 → 草稿 |
| 外部更新（静默） | 收到广播且不在编辑中 | 无提示，内容替换；位置变化则平滑移动 0.2s | 正常 | — |
| 外部更新（冲突） | 正在编辑且远端 `updated_at` 更新 | 抽屉顶部黄条二选一 | 「载入最新」/「保留我的」 | 选择后回草稿 |
| 已删除 | 确认删除 | 淡出 0.12s，其关联同步消失 | 撤销（5s） | 撤销 → 原位置 / 原父级 / 原 sort |

### 9.2 删除节点的子树处置（必须二选一，不许默认粗暴级联）

| 选项 | 行为 | 何时默认 |
|---|---|---|
| A. 连同下级一起删 | 删除该节点及全部后代 + 所有相关关联 | 有 ≥1 个子节点时的高亮项，确认文案写明数量 |
| B. 只删这个，下级提升一级 | 子节点挂到被删节点的父节点下（被删的是根则子节点变根），顺序追加末尾 | 次要选项 |
| 关联 | 两种选项都删除所有 `from/to` 命中该节点的关联 | 固定行为 |

### 9.3 画布与视图状态

| 状态 | 触发 | 表现 |
|---|---|---|
| 加载中 | 首次进入 / 切作品 | 网格底纹 + 书纲骨架 + 3 个节点骨架；<300ms 不显示 |
| 就绪 | 数据返回 | 渲染画布，恢复上次视口（无记录则「适应内容」） |
| 空 | 零节点且书纲四段全空 | 中心幽灵书纲节点 + 三入口（§11.1） |
| 聚光中 | 选中搜索结果 | 非命中 20%，命中脉冲 1.5s |
| 仅显示分支 | `Ctrl+Shift+F` | 非当前子树 15%，顶部提示条「仅显示该分支 · 退出」 |
| 错误 | 读取失败 | 整页错误态 + 重试 + 诊断日志 |
| 降级渲染 | 节点 >300 或边 >500 | 边切 Canvas、关阴影；无提示（静默） |

| **FR-38** | **画布框架** | 落地用 `@xyflow/react` + `elkjs`；节点卡为自定义节点组件（吃 `--app-*`），连线层自绘（§8.12.2）；框架只做视口/命中/渲染，数据与状态仍在 Zustand | 迁移审查：与框架相关的代码只出现在画布组件目录，store 与 handler 无框架 import |

### 18.3 与既有功能的边界

| 既有功能 | 与大纲的关系 |
|---|---|
| 右侧「伏笔埋设」面板 | 只改名，功能与数据零改动；渲染章节域既有物 |
| 章节树 / 编辑器 | 不读大纲、不因大纲变化而变；建章流程完全独立 |
| 灵感池 | 单向「转为节点」；转换后互不引用 |
| AI 上下文 | 可读节点与关联（已落库版本）用于生成引导；不写回；不读章节进度做对照 |
| 回收站 | 大纲节点不进回收站（无正文、重录成本低），靠 5s 撤销兜底，差异在帮助手册注明 |

本方案为产品设计参考，具体实施请结合仓库规范（`AGENTS.md`）与评审结论确认。
